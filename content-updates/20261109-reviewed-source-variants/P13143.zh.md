# Lollipop Shop

## 题目描述

你经营着一家棒棒糖店。每天开始时，你制作 $N$ 根棒棒糖，每根都有一种独一无二的口味，例如越橘、樱桃或青柠。当天有 $N$ 名顾客依次进店，每名顾客会告诉你自己喜欢哪些口味。只要某种口味之前还没卖给其他顾客，你就可以把该口味的一根棒棒糖卖给当前顾客，因为每种口味只有一根。若顾客喜欢的所有口味都已经售出，就无法卖给他棒棒糖，他只能失望地离开。

在顾客到来之前，你不知道他喜欢哪些口味。每名顾客是否喜欢某种口味都是随机决定的，并且独立于他是否喜欢其他口味，以及其他顾客的喜好。不过，市场调查表明，有些口味总体上更受欢迎。例如，每名顾客喜欢青柠口味的概率可能为 $10\%$，而喜欢樱桃口味的概率可能为 $1\%$。每种口味对应的喜欢概率，均从区间 $[0.005, 0.1]$ 中独立、均匀随机选取。

显然，你希望尽可能多地卖出棒棒糖，让这 $N$ 名顾客尽量满意！但由于无法预先知道后续顾客的喜好，并不总能作出最优选择：有时你给当前顾客卖出一种口味，之后才发现，当时卖给他另一种口味会更好。

假设你预先知道了所有顾客的喜好并能提前规划，此时最多能卖出 $M$ 根棒棒糖。虽然你实际上并不知道后续喜好，但对于每个测试用例，仍要求你卖出的棒棒糖数量至少达到 $M$ 的 $90\%$。

### 交互协议

这是一道交互题，输入输出与普通 Code Jam 题目不同。你需要与一个独立的进程交互，由它提供信息并判断你的回答。所有信息从标准输入读入，向评测器发送的内容必须写到标准输出。许多语言默认会缓冲输出，因此在阻塞等待回应前，要确保内容已真正输出，例如刷新输出缓冲区。原 FAQ 中有关于刷新缓冲区的说明。标准错误输出中的内容会被忽略，但它可能占用内存并计入内存限制，因此不要无限输出。

程序首先应读入一行一个整数 $\mathbf{T}$，表示测试用例数，然后依次处理 $\mathbf{T}$ 个测试用例。

每个测试用例开始时，读入一行一个整数 $\mathbf{N}$，表示棒棒糖数量，同时也是顾客数量。

接下来依次处理每名顾客。对于每名顾客，读入一行用空格分隔的整数。第一个整数为 $\mathbf{D}$，表示该顾客喜欢的口味数量；后面跟着 $\mathbf{D}$ 个严格递增的整数，表示这些口味的编号。每种口味的编号唯一，范围为 $[0, \mathbf{N} - 1]$。某些顾客甚至所有顾客的 $\mathbf{D}$ 都可能为零。

每次读入上述一行后，必须向标准输出写入一行，包含你决定卖给该顾客的某种口味编号，该编号必须属于他喜欢的 $\mathbf{D}$ 种口味；若不出售，则输出 -1。输出本组的第 $\mathbf{N}$ 行后，若这是最后一组测试数据，则程序应结束；否则继续读入下一组数据。

若程序出现错误，例如卖出了已经售出的口味、卖出了顾客不喜欢的口味、输出格式错误或数值越界，评测器会向输入流发送 -1，此后不再发送任何内容。若程序收到 -1 后继续等待，就会超时并得到 Time Limit Exceeded。你应及时终止程序，以获得应有的评测结果（例如 Wrong Answer 或 Runtime Error），而不是由于等待导致的 Time Limit Exceeded。和通常情况一样，总运行时间或内存超限、运行错误都会得到相应评测结果。某组卖出的棒棒糖数量未达到要求，并不会触发这里的 -1 消息。

所有测试用例处理完后，不应继续向评测器发送额外内容。也就是说，若程序在最后一组之后继续向标准输出打印，会得到 Wrong Answer。

## 提示

注意，下面交互示例中的 $\mathbf T$ 和 $\mathbf N$ 小于真实数据；本地测试工具使用的数据规模也更小。

```
  t = readline_int()           // reads 10 into t
  n = readline_int()           // reads 4 into n (four customers & flavors)
  prefs = readline_int_list()  // reads 1 2 (customer only likes flavor 2)
  printline 2 to stdout        // sells this customer flavor 2
  flush stdout
  prefs = readline_int_list()  // reads 0 (customer likes nothing)
  printline -1 to stdout       // no flavor to sell to the customer!
  flush stdout
  prefs = readline_int_list()  // reads 1 2 (customer only likes flavor 2)
  printline -1 to stdout       // already used flavor 2, so no flavor to sell
  flush stdout
  prefs = readline_int_list()  // reads 2 1 3 (customer likes 1 and 3)
  printline 3 to stdout        // note: we could have also sold flavor 1
  flush stdout
  n = readline_int()           // (start of case 2) reads 1
  prefs = readline_int_list()  // reads 1 0
  printline -1 to stdout       // non-optimal but legal choice
  flush stdout
  n = readline_int()           // (start of case 3) reads 5
  prefs = readline_int_list()  // reads 2 1 3
  printline 1 to stdout
  flush stdout
  prefs = readline_int_list()  // reads 2 1 2
  printline 1 to stdout        // error -- tried to give same flavor twice!
  flush stdout
  prefs = readline_int_list()  // reads -1 (judge has given up on us)
  exit                         // exits to avoid an ambiguous TLE error
```

以上伪代码展示了如下情形。

- 第一组中，程序共卖出两根棒棒糖，而最多也只能卖出两根，因此实际卖出数量至少达到了最大可能数量的 90%。
- 第二组中，为了展示交互，程序明明可以出售一根棒棒糖，却选择不卖。它本可以卖出 1 根，实际却卖出了 0 根。因此程序不能通过这组测试，但注意，评测器不会因此停止发送输入。
- 第三组中，程序又为了演示而进行了一次非法操作，导致评测器停止发送输入。程序识别出这一情况并终止，最终会得到 Wrong Answer。

你可以使用题目专用测试工具，在本地或原平台测试程序。在本地测试时，需要让测试工具与你的程序并行运行；可以使用原有的 [interactive runner](https://storage.googleapis.com/coding-competitions.appspot.com/interactive_runner.py)，具体使用方式见该脚本中的注释。

测试工具的使用说明写在工具自身的注释中，也鼓励你添加自己的测试数据。请注意，虽然测试工具旨在模拟评测系统，但它**不是**真正的评测系统，行为可能与实际评测器不同。

**关于评测器行为**

每组测试开始时，评测器就会决定所有顾客的喜好。具体而言，每种口味都有一个位于 0.005 到 0.1 之间的隐藏概率 $P_i$，每名顾客喜欢第 i 种口味的概率为 $P_i$。对于固定的口味 i，各顾客 j 是否喜欢它的随机变量相互独立且同分布。这些喜好在整组测试中保持不变，不会根据你的选择而调整。

**测试集 1（29 分，公开评测）**

- $\mathbf{T} = 50.$
- $\mathbf{N} = 200.$
- $0 \leqslant \mathbf{D} \leqslant \mathbf{N}.$
