# 三人团队训练

团队入口位于原有“排行榜 → 团队训练”，使用三个真实账号组成队伍。队长选择服务端题单与 5–300 分钟的时长，三人在线并准备后开始。缺失题面保留原题号并禁用，其他题目正常进入。

## 共同比赛与代码

共享服务维护成员、比赛时间、冻结题单、当前题目及编辑租约。全队同时只有一名编辑；其余两人只读观看。租约十五秒到期，只有正在打开这场训练的窗口才能续租，断线后其他队员可以取得编辑权。草稿按题目分别保存，用版本比较防止旧代码覆盖新稿；写操作携带稳定的请求编号，网络重试返回同一次操作的结果。

前端复用既有 Workbench、C++17 / Python 3 编辑器、题面、中文切换、运行区、原站浏览器与全屏快捷键。普通个人草稿和团队草稿分别保存；断线时的未发送代码留在当前账号本机，切题、刷新及结束后仍可从相应题目复制恢复，不擅自覆盖当前共享稿。运行区拖动高度按账号及房间恢复。

## 正式回执

正式运行或提交前，服务端授权精确的房间、题目、代码版本、语言和代码摘要。原站浏览器启动前先持久化提交意图；同一意图重试只返回原会话，状态不明确时不再次提交。重启后，只有与原比赛、原代码和启动时刻唯一对应的已保存正式记录才可恢复；同码多次尝试存在歧义时保留待确认。

本机将真实正式记录放入持久化待发送队列，只发送提交编号、授权编号和原站账号。共享服务再次读取原站公开记录，独立核对账号、题目、提交时刻及最终结果，不接受界面提供的 AC、时间或分数。Codeforces 使用官方 API；牛客使用公开提交榜；AtCoder 使用 AtCoder Problems 的第三方公开记录，保留来源标识。提供商不可用时保持待确认。

团队成绩为比赛窗口内已核实正式 AC 的题目并集。同一题反复通过只计一题；以前个人通过过的题，在本场重新正式通过仍可计分。队友的通过不会写成自己的提交、首次 AC、复习或奖励，本地样例也不计团队 AC。原有个人正式提交记录继续保留。

## 数据与接口

`server/leaderboard/mysql/019_team_training.sql` 新增八张专用表，`020_team_native_receipts.sql` 新增一张正式回执表，不改写已有业务表。生产和 SQLite 隔离验证使用相同的团队业务与 HTTP 路由。原站核验在事务外执行，提交前重新校验会话和房间。

接口统一位于 `/v1/team-training/`，本机入口为 `/api/team-training/`。身份来自有效登录会话，禁止调用方指定其他用户；同一账号同时只属于一个队伍。历史代码仅限冻结的真实参赛成员读取，新加入成员不能读取以前的私有比赛代码。

## 本轮验证与交付边界

三套真实浏览器上下文、三个独立本机 Python API 和共享 HTTP 服务已验证同时准备、唯一编辑、中文及非 BMP 草稿同步、失联接管、私有缓冲保留、切题与重启恢复、缺题禁用、运行区持久化、结束及历史。正式提交链在此使用明确的确定性提供商验证，实际原站提交数为零；另以只读公开记录独立验证三个真实提供商的解析和请求。
