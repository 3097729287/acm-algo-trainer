# 共享服务 1.4.2 修复候选

本候选尚未部署，生产基线仍为 1.4.1。本机桌面更新与线上服务部署分别验收、分别授权。

普通训练账号拥有管理权限时，旧筛选错误地隐藏了其所有榜单成绩与互动入口。新筛选只排除登录名为 `admin` 的专用维护账号，保留正常账号的真实首次 AC、自身排名、留言与爱心。管理操作仍使用既有服务端角色鉴权，不修改任何账号角色、历史成绩、奖励或排除记录。

头像保存原始 PNG、JPEG、WebP 字节，最大 12,000,000 字节，保留像素和文件摘要。兼容原有 `publicAppearanceProtocol:1`，通过 `originalAvatarProtocol:1` 声明较大原图能力；排行榜正文仍只携带摘要。上传在读取大请求体前鉴权、限制同时请求数，头像缓存设置总量限制。专用 Caddy 路由只放宽 `PUT /v1/profile` 至 16,065,568 字节，普通接口、账号状态和分块接口原有限额保持。

放置与回收在幂等写入提交后附上当前可信库存，减少一次额外网络往返；持久操作账本仍只保存小型确认回执。

验证包括原共享服务套件，以及普通管理权限账号与专用维护账号的区别、原图经实际 HTTP 上传与读取后逐字相同、单次响应回收与请求重放、Caddy 精确路由补丁和未知配置拒绝。SQLite 协议验证不冒充生产 MySQL 验收。

部署包由 `prepare-account-sync-runtime.py` 从同一干净提交准备，包含 SHA-256 文件清单。`deploy-feedback.sh` 保留原配置、完整数据库压缩备份和旧运行时，停写后比较全部数据表指纹，不执行 SQL 迁移。代理配置先验证再加载，失败恢复原运行时与原 Caddyfile，不用旧备份覆盖新的用户数据。部分备份或失败候选保留，脚本不永久清理它们。
