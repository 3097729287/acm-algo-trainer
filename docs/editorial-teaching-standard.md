# 题解与基础知识的教学要求

2026-10-22 用户根据《小月的长廊》的实际阅读反馈明确要求。本规范适用于全部存量题解的翻新和以后的题解；创作范围继续遵守 [题解政策](editorial-policy.md)，不删除已有内容。

题解须让第一次接触这些工具的读者理解推理并读懂关键代码。算法正确、公式正确、代码通过和格式检查通过，都不能单独证明教学完成。

## 多种解法与两种篇幅（2026-10-30 用户确认）

一道题有多种有教学价值的解法时，可以分别编写。每一种算法都必须有独立的默认题解与详细题解，组织层级为“题目 → 解法 → 默认版 / 详细版”。这覆盖旧的“一题只写一条解法”限制；不要求为直接算术题硬凑多解。

默认版交代该解法的关键观察、必要理由、实现、复杂度、参考代码与边界；详细版从具体例子展开该解法的推导、基础工具与代码对应。两版共享同一份已验证参考程序，不能用复制同一正文或只有标题的占位表示完成。不同解法分别验证；适用条件、复杂度及选择理由写清。

TB 使用现有 `solution_methods` 保存各解法的双版正文；主解法兼容原有 `solutions` / `detailed_solutions` 入口。每个方法单独关联实际知识点。原有解法、已验证代码及图片保留。

## 题目里的推理

先用具体对象解释准备计算什么。公式中的集合、加减项、因子、边界都要说明来源，再连接代码。出现区间覆盖、集合相减、树边、几何位置、状态依赖或读写变化时，画能表达这些关系的图；图与相应推导相邻，不能用数表替代需要看位置的图。无需给直接算术强行配图。

例如覆盖计数要画出同一条数轴上的区间和查询线，区分已经结束、仍然覆盖、尚未开始，另标端点等于查询点的情形。说明被减集合为什么包含在被加集合中，再写差值。图例同时用文字与颜色，图中数字须与正文可互相核对，实际检查宽窄屏、深浅主题的渲染。

## 独立的从零讲

算法之外的 C++ 工具、标准库函数和语言写法也属于必要知识。看到 `lower_bound`、`upper_bound`、lambda、迭代器相减、结构化绑定、自定义比较器、位操作或递归等，不得把“代码里用过”当作“已经解释”。按实际代码用法选择知识，不按题目标签猜测实现。

基础课解释统一的使用场景、语法、输入和返回值、最小例子、成立条件、优势及限制。按照概念增加必要内容，不逐项填同一张空模板：

- 二分边界函数：有序/分段前提、左闭右开范围、返回迭代器而非计数、重复值、`end()`、下标与数量之间的关系、四种大小比较的计数、二分查找实现与循环区间、为什么是对数复杂度；说明非随机访问迭代器的移动成本和关联容器成员函数。
- lambda：定义与调用、参数和返回值、`[]`、`[x]`、`[&x]`、`[=]`、`[&]` 的捕获含义、何时使用、局部辅助函数与比较器的优势、引用生命周期和按值捕获的快照、递归写法、`std::function` 的取舍。不能把匿名函数本身说成算法优化。
- 容器：数据组织、操作与各自复杂度、失效规则、空容器及访问前提。数学方法说明它处理的对象、前提与推导，避免只列 API。
- DP：先定义状态所回答的独立问题，再讲起点、来源、计算顺序与优化后的读写版本。图中显示完整运算数。

基础课应脱离某道题仍能阅读和迁移。题解提供完整的折叠从零讲和精确知识关联；同一来源同时供“从零讲”页面展示，避免维护两份不同的说明。题目特有的公式解释和代码对应关系保持在正文中，不外包给折叠内容。

## 翻新与验收

保留题目身份、题意、原题链接、已验证的参考程序、有效推导和既有图片。两种版本均补齐缺失入口，详细版保留更细的推导；不得把两版简单复制成同一篇。新增的教学代码片段与参考程序明确区分。

用实际程序识别工具，并复核匹配处的语义，避免把输入输出 `<<` 当位移、把数组下标当 lambda、把无序查找与有序二分混淆。通用教程图用于解释知识；需要题目图的推理另外补画，不能用通用流程框图宣称已经解释了任意公式。

验证文字里的例子、二分边界、闭区间端点、教程代码与生命周期说明，检查所有图片实际能显示；核对翻新前后参考程序逐字一致、既有知识与图片保留、SQLite 与文本源一致、精确知识关联在 UI 中可展开。使用一次性状态，保留个人训练、代码、身份和导入内容。不将机器覆盖率说成全部逐题人工审阅，也不将未打包内容说成已安装。
