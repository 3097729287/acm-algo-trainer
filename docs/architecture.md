# TB 架构

本文包含本地 v0.10.4 的账号升级；[账号说明](accounts.md)。最近正式发布记录见 [v0.10.1](releases/0.10.1.md)。

## 边界

`frontend/` 只负责界面、编辑器与交互，通过 JSON HTTP API 调用服务；不导入 Python 或读取归档文件。`backend/` 管理题库、个人记录、公开数据、翻译和本地评测，可以只启动 API。`desktop/` 创建 WebView2 工作台窗口，并通过随包的浏览器扩展连接用户日常浏览器中的原站会话。`server/leaderboard/` 是可独立部署的共享服务。

开发入口：`python backend/backend.py --offline` 与 `frontend/npm run dev`。Vite 代理 `/api` 并保留会话令牌。若直接跨源连接，使用 `TB_FRONTEND_ORIGINS` 显式配置允许的来源，多个来源以逗号分隔；未配置时仍执行同源校验。API 只监听回环地址，写入要求 `X-TB-Token`。

## 数据与迁移

| 文件 | 内容 | 分发与升级 |
| --- | --- | --- |
| `data/library/` | 公共题目、题面、题解、讲义及精确关系（文本 JSON 源） | git 管理的可 diff 文本；首次启动或打包时重建 |
| `data/library.sqlite3` | 由文本源重建的二进制题库 | 随包分发，无个人进度；构建产物，不进入 git |
| `state/tb-library.sqlite3` | 可更新的题库工作副本、导入内容、抓取题面 | 首次合并内置库，后续按来源摘要合并；保护本地修改 |
| `state/tb-personal.sqlite3` | 训练、提交代码、草稿、模拟赛、身份、任务和经验 | 永不由安装包覆盖 |
| `state/accounts/<内部 ID>/tb-personal.sqlite3` | 切换到其他注册账号后的个人记录 | 与原工作区隔离；不覆盖已有记录 |
| `state/tb-documents.sqlite3` 及缓存子目录同名数据库 | 设置、加密翻译凭据、公开 HTTP 缓存、知识分析等 JSON 形状文档 | SQLite 事务写入；旧 JSON 只迁入一次 |
| `state/backups/` | 升级、导入前的 SQLite 在线备份 | 保留已提交 WAL 内容 |

`data/library/` 下是随包题库的文本源：`meta.json`、`problems.json`、`solutions.json`、`statements.json`、`lectures.json`、`links.json`。`data/library.sqlite3` 是构建产物，不被 git 跟踪：首次启动时若缺失会由 `backend/store.py` 自动重建，`scripts/build_release.py` 打包时同样保证重建，`scripts/check.py` 校验前也会补齐。维护者用 `python scripts/library_seed.py export` 从 sqlite 导出文本源，用 `python scripts/library_seed.py build` 重建 sqlite。内容升级按文本源指纹（`bundled_sha256`）判定，与 sqlite 文件字节无关。

`TB_STATE_DIR` 可覆盖状态目录，`TB_LIBRARY_DB` 可指定工作题库，`TB_ARCHIVE_ROOT` 指定显式导入/收件箱根目录，`TB_BACKUP_DIR` 可指定个人记录备份目录。默认状态在程序目录的 `state/`；Windows 安装到当前用户可写目录。

旧 JSON 文件保留字节不变，后续读写 SQLite。Windows API Key 仍使用用户绑定的 DPAPI 加密，不进入公共题库、响应或日志。0.5 个人数据库保留原有表和数据，由训练服务进行兼容升级。`--migrate-local` 只在用户选择旧安装导入时运行，复制允许的状态和设置；在线备份支持旧进程的已提交 WAL。升级安装不会重新导入另一份身份，也不会覆盖现有目标。

公共库升级按表记录上次分发内容的摘要。只有未在本机修改的内容随新版本更新；用户导入、修改和后来抓取的题面保留。事务失败回滚，外键与完整性检查拒绝损坏内容。新库与个人记录分开，卸载保留运行后产生的状态目录。

Markdown 是正文格式与交换格式，运行时不通过路径定位题解。`scripts/import_library.py` 和收件箱处理负责显式导入旧归档；旧源文件保留。收件箱在提交前校验章节、冲突和讲义，正文与引用关系一起入库。

## 题解与讲义

题目 ID 与原站规范化 URL 索引共同定位内容。同题不同 URL 写法可共用已收录的题解、题面和讲义。基础讲解关联分为本题自己的章节和明确引用；不按共享标签扩散。正文摘要用于去掉重复的关系，保留不同的推导。前端将正文中的从零讲章节折叠，按需展开。

题解和讲义的本地配图在显式导入时一并嵌入 SQLite，运行时不依赖原始 Markdown 或图片目录。支持 SVG、PNG、JPEG、GIF、WebP、AVIF、BMP；相对路径、中文文件名和 Markdown 引用式图片在导入时解析。外部 HTTP 图片保持原链接。题解页、讲义页和折叠讲义共享图片组件，可点击查看原尺寸，Esc 关闭并返回阅读位置。

内容版本升级替换未修改的内置讲义；旧讲义只有在没有关系引用且内容仍等于上次分发摘要时才清理，用户修改及自建引用保留。经审阅的图文稿保留原推导，讲义只补本题题意和应用位置，不重复套入通用基础模板。

## 外部接口

翻译只发送公开英文题面，拆分请求时保护公式、代码、样例、数字和格式；截断或标记变化拒绝写入缓存，原文始终可读。自定义服务支持 Base URL 归一化、模型 ID 和可选密钥。连接测试真实调用用户配置的服务，产生普通翻译 API 用量。

官方适配按网站识别实际语言控件，区分编译器版本与 C++ 标准，触发正常表单事件。登录、验证码和 CSRF 保留原站流程；需要登录或没有匹配编译器时向用户报告原因。

单题工作台的“运行样例”调用本地运行接口，“提交”进入 `BrowserBridge`，由 `SilentSubmitter` 创建不可见的 WebView2 子控件。四个平台各使用独立的 `tb-cf/tb-atcoder/tb-nowcoder/tb-luogu` WebView2 profile；既不创建系统浏览器窗口或标签，也不打开应用内登录页。提交继续使用原站页面、CSRF 和同源请求。只有用户明确点击连接、登录或验证按钮才打开浏览器。

`BrowserSessions` 通过已启用的 Edge/Chrome 扩展同步四站会话 Cookie。扩展仅拥有这四个域和回环地址权限，不读取密码。同步必须先由本次任务发起，校验平台、域名、随机 nonce、固定扩展 ID、严格 Origin 和客户端能力令牌；拒绝跨站 Cookie、过量数据和重复覆盖。登录快照以当前 Windows 用户绑定的 DPAPI 加密保存于个人 state/browser-sessions.dpapi，最长缓存七天，空快照代表浏览器已经退出登录。缓存有效时不需要浏览器保持运行；需要刷新时 `silent_browser` 只寻找安装了此连接扩展的标准浏览器配置，用 `--no-startup-window` 无窗口唤醒，不读取、复制或解密浏览器的 Cookie 数据库，不终止用户浏览器。

0.10.3 的扩展协议 3 可在一次队列请求中同步登录与处理明确分配的后台标签任务。Codeforces 在已有浏览器窗口时优先使用该浏览器的登录会话；按正在打开的平台选择浏览器配置，不切换前台标签。浏览器关闭时继续使用原生后台组件。协议 2 保留兼容路径；未接收的任务在三秒后交回原生组件。每个提交独占一种传输，只有点击前可以切换；已持久化提交检查点或取得受理编号后禁止切换和重发。HTTP exchange 仅允许被明确分配给浏览器的任务，其他原生任务继续拒绝浏览器事件。重新加载 0.10.3 扩展后启用浏览器窗口与平台识别，权限范围不扩大。

AtCoder 的个人记录页通过精确回跳路径、登录用户和表格或 `.panel-body` 中的明确空记录状态识别，首次在比赛中提交不再因没有表格而失败。提交前记录提前查询，Codeforces 的两份个人记录与官方用户 API 并行取首个有效快照；保留账号、题目、编号下界和受理检查。后台组件在 DOM 解析完成时立即检查表单，无须等待图片和其他资源全部加载；记录查询保持单个在途请求，避免慢请求积压。

每次提交冻结题目和代码，通过 BrowserBridge 的同一套能力、比赛锁和持久化校验。JS checkpoint 获得宿主确认后才发送一次 POST；请求只表示已发送，收到正整数提交编号才表示受理。准备超过 40 秒明确失败，45 秒没有受理编号标记未确认并继续接受迟到回执，最长 15 分钟，不自动重发。登录/验证完成需要用户再次点击提交。成功后保存 scope=official 记录、更新进度及原有 AC 字号和音效，释放隐藏控件。

牛客旧编辑器调用原站 `/nccommon/submit_cd`，按 submissionId 查询 `/nccommon/status`，兼容顶层/data 回执；新版编辑器仍观察 document_start 的 fetch/XHR 与 Victorinox 请求。洛谷从 lentille-context 或 content-only 题目接口获取本题、账号及允许语言，再从官方配置确认提交路由，携带本页 CSRF POST `/fe/api/problem/submit/{pid}`，按 rid 查询 `/record/{rid}`。洛谷不再以“找到编辑器”作为就绪条件，不依赖异步编辑器实例；接口上下文错误会明确终止。CF、AtCoder 保留原站表单和语言选择，从本账号的提交前快照与后续记录识别新结果。四站没有统一公开的代码提交 API，网页接口不称为公开开放 API。

验证区分测试接口与真实账号。`desktop/tests/silent_native.py` 在真实隐藏 WebView2 中拦截全部网络，验证四站提交、cookie 复用、加密缓存重启、洛谷未挂载编辑器、缺失上下文、登录重试及回执；`frontend/tests/silent-browser.mjs` 使用可丢弃 Edge 配置，验证完全关闭后无窗口冷启动和四站登录同步。任何适配器测试均不向用户账号提交代码。

排行榜服务为阿里云 `https://47.82.84.74`，1 GiB 实例已完成部署、重启恢复及真实客户端连接验证。生产服务使用 Node.js、MySQL、Redis 和 Caddy HTTPS；旧服务器已退役，4 个原身份已导入 MySQL，私有备份已下载并核验。客户端上传已持久化的 `scope=official` 原站 AC 回执；按规范化原题去重，确认服务器完整接收后记本地收据。新回执自动触发同步，失败后台重试，启动时补传历史记录。`official_ac_events` 单独计分，旧本地记录表保留但不混入官方榜。只上传题目哈希、首次受理时间和难度，不上传代码或站点 Cookie；服务尚不进行独立原站防作弊复核。0.10.4 起整个软件先登录再进入；注册填写昵称、登录号和密码，旧安装凭据仅用于一次性关联原身份。密码摘要与可撤销会话在共享服务保存，本机令牌使用 DPAPI 加密存入 SQLite，不交给前端。切换账号使用独立个人工作区和浏览器草稿，界面在同步完成后刷新。测试用 `TB_OFFLINE=1` 或本地服务，避免生成测试用户。协议和部署见共享服务目录。

## 排行榜奖牌与奖励

排行榜奖牌、经验与管理功能从本机 0.10.2 更新引入。共享服务以北京时间日界线和周日界线保存不可重复的周期结算、奖励与结算游标；重启补结算已完成的周期。奖励总额经注册账号会话认证后同步到本机 `ranking_reward_totals`，当前连接对应的奖励计入成长，避免跨服务迁移时重复叠加。排行榜同题数按首次完成时间、用户 ID 确定三个独立席位。管理员角色只来自共享数据库 `ranking_admins`；客户端本机会话认证、服务器账号会话认证和事务内角色校验共同保护删除。删除标记与审计独立保存，不删除身份或本机训练，不因重传旧回执恢复。

## 软件自动更新

`backend/software_updates.py` 固定读取本项目 GitHub Releases 的最新正式版本，启动后后台检查，并每 24 小时重查；用户可关闭自动检查或手动检查。版本按三段数字比较，预发布不安装。仅接受指定仓库对应版本的 x64 安装包、GitHub 返回的 SHA-256 和有界大小；下载跳转只允许 GitHub 的 HTTPS 资产主机。系统代理共享匿名查询额度耗尽（HTTP 403 且剩余额度为 0）时，v0.10.1 尝试一次直接 HTTPS 查询。断网、限流与损坏文件均保留当前程序，可重试。

本机写接口要求会话令牌。安装按钮先等待工作台草稿保存，待处理官方提交或进行中的模拟赛会阻止安装。安装前以 SQLite 在线备份保留 WAL 数据；外部 PowerShell 助手等待进程正常退出，再次校验 SHA-256，使用 Inno 安装程序原地更新并重新打开 TB。安装包不包含个人 state/cache/backups，目标路径来自当前程序，不能由远程更新信息指定。安装失败记录在 cache/updates/install-result.txt。安装校验只证明文件与 GitHub 发布资产一致，不替代代码签名。
