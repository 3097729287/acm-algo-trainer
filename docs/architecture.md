## 1.3.4 当前边界

`training/start` 的可选布尔字段 `assisted` 复用 `solution_seen_at` 记录已看过的跟做指导，沿用模拟赛的题解锁；交接不伪造提交或通过，也不改写旧提交的独立性。未看指导直接实现时仍用原来的默认行为。

跟做页面接收当前考场题目，按题目编号、别名及规范原题链接锁定对应指导，交卷后恢复；同题换编号不能在跟做页面绕过锁定。

`reviews.py` 从官方回执和规范原题派生动态复习。逐题状态、每轮任务、当天预算以及原站会话与回执关联复用 `account_preferences`；每轮草稿使用 `review:<taskId>` 上下文。接口的可选 `reviewId` 必须属于该题且与考场互斥。历史作答不清空、样例不算通过，辅助通过次日再练。没有新增数据库表或共享服务协议。[规则与来源](adaptive-reviews.md)。

`catalog_identity.py` 在读取边界按规范 URL 去重，响应附 `aliasIds`；旧数据库行、草稿、记录不改编号。雷达一次建立题目知识索引并缓存所有层级汇总。成长缓存以真实写入、日期和内容摘要失效，无变化轮询复用结果。

`contest_calendar.py` 延迟创建，公开一方 GET 在后台线程更新，返回缓存不阻塞启动。四站适配限定基础赛事，归一 UTC 后按北京时间显示；失败不清空有效缓存。日历只读，不报名或提交代码。

24 篇新增基础讲解由已审阅的详细题解“思路”抽取，保留题意、正文、图片和内容哈希，精确链接原题；`scripts/extract_foundations.py` 默认 dry run，显式写入才备份并追加公开 JSON，再生成公共 SQLite，不访问个人库或写原归档。

## 1.3.3 延续边界

知识点以 `knowledge.py` 的规范树和别名为统一来源，前端雷达从同一目录提取可展示子项；题库、统计和筛选经 `canonicalKnowledgeName` / `matchesKnowledge` 匹配。掌握度 v3 按唯一原题的解决、独立性、稳定性、难度与题量估计，大类要求每个子项至少 5 道有效题、3 道有难度，且总样本不少于子项数的 5 倍。未知项保持 `null`，不参与伪造零值，旧 XP 与段位账本不变。

预置翻译保存在公开 statement 的 `translation` 字段，含原文 SHA-256 与格式标记。读题前验证完整正文及公式、代码、样例等不可变内容；种子合并只为相同原文补充译文，不覆盖本地编辑或更高来源的译文。原文、结构化样例和限制不改写；显示默认中文，原文随时可选，预置内容不访问翻译 API。

管理员版以独立 EXE、Inno AppId、安装目录和 `admin-workspace` 运行。普通模式管理接口不可用；管理员的本地等级实验不进入共享成绩。公共榜单操作由 `AdminRanking` 使用固定 `admin` 登录，在服务器验证角色；会话以本机 DPAPI 加密保存，过期、撤权与退出清除，不同步用户学习快照。不修改共享服务协议或数据表。

新手指引分入门总览和设置内的各页目录；首次账号进入启动总览，完成状态复用私有偏好。各页指引只导航与高亮，不自动提交、改头像、创建考场或发消息。比赛与重现赛复用同一目录分类与时间排序；已知但尚未收录的赛事保留空目录。

## 1.3.2 界面与证据模型

知识掌握不再用题库覆盖率。`knowledge_mastery.py` 从结束的原站正式提交及精确匹配的公开 AC 构造每题证据，排除运行、样例通过、CE 与基础设施错误。同原题按 URL 归一，解决率 50、独立完成 20、首次通过前提交稳定性 15、已知难度表现 15 加权；未知难度不补造分值。至少 5 道不同有效题且至少 3 道已知难度才输出数值，否则 `mastery:null`。接口附带 `knowledgeEvidence`、标签 `evidenceIds` 与模型门槛，前端按唯一题目集合汇总大类；未知项不画成零。模型不写回 XP、段位和旧记录。

全部计时模式均可用已校验的 `contestId` 进入原生浏览器提交，回执轮询按同一考场上下文校验，原站回执按实际提交时刻关联比赛。题解锁、结束后的只读限制和无考场上下文的旁路限制继续生效；历史本地记录保留。无数据库 schema、账号协议或共享服务变更。

`FolderSelect` 保留原生表单取值，门户浮层逐层展示目录与可选择父主题。模拟赛选题菜单同样通过门户渲染，防止紧凑工具栏裁剪。设置返回控件共享，静态说明通过 Tooltip 提供；账号同步预留固定 18px 槽位。默认组题时长由模式、难度与题数计算，重现赛使用元数据，用户手动时长保留。

## 1.1.4 运行环境与响应

本地编译和每次运行显式传递工具链 bin 在前的子进程 PATH，过滤冻结运行时目录；在共享启动锁内临时清除继承的 DLL 搜索目录，创建进程后恢复。Windows Job 限制保持。成功编译的可执行字节仅在当前 Judge 内存中缓存，键含代码 SHA-256、编译器路径、时间戳及大小，至多 8 项 / 16 MiB；每次仍写入新的私有临时目录并执行输入，不保存运行答案。错误编译和取消结果不缓存。

成长统计缓存最多 3 秒，以连接、个人库变更、北京时间日期、公开账号和公共库摘要失效；返回深复制，新增成就经验不重复通知。任务领取只等待持久化事务与任务状态，前端随后异步刷新成长，不再同步重算全部统计。次要页面按需导入。

`GET /api/data/export` 沿用本机来源与已登录账号守卫，仅查询当前账号的学习表白名单，返回 `tb-learning-export` / `formatVersion: 1` JSON；不写入 SQLite，不读取排名鉴权、浏览器或翻译密钥文档。新手指引完成状态和平台显示开关属于账号偏好，完成状态合并时保留 true。新注册登录触发一次，老账号不强制弹出。

题面格式转换只处理公开抓取与显示，保留 HTML 数学、列表、代码和表格；结构化样例保留官方换行。旧牛客缓存非阻塞刷新至 statementVersion 3。浏览器在新文档预装原站适配脚本，短轮询只调用现有函数；原生表单、CSRF、登录与提交确认边界不变。

## 1.1.2 重现赛、会话与快照恢复

重现赛的原站提交与盲组题模拟赛分开授权：`assert_official_allowed` 只允许重现赛走可见原生表单，题解与考点仍锁定。官方回执使用 `contest_id` 关联考场，按受理时间判断本场归属，合并公开同步先到的同一回执及别名题；样例不计作 AC。重现赛禁止旧的本地 submit，run 仍可校验样例。

考场冻结题单记录 `trainingAdded`。显式加入或独立练习会保留个人训练归属；删除重现赛只停用其独立创建、没有其他引用的训练，不删除草稿与提交。记录仍以墓碑保存，迟到回执落库而不重新激活已删除项。

`BrowserProcess` 复用专用浏览器配置，并核对 DevToolsActivePort 的浏览器 GUID。`browser_login_memory.py` 仅保存该配置内四站的一方 Cookie，Windows DPAPI 密文写入本机 SQLite；重启补回缺失且未过期的会话，退出原站的空会话同样持久化。日常浏览器不参与读取，Cookie 不进入账号同步、安装包或公共库。监测只在专用浏览器已经打开时运行。

客户端仅在本机内容摘要与已同步基线一致时发送 `X-TB-State-Revision`。服务器先验证会话，再确认版本；匹配时返回 `{revision,unchanged:true}`，不读取大快照。版本不同或旧服务不支持时继续完整 GET 与合并；未认证响应不能打开工作区。

个人库普通 `_write` 将完整在线恢复副本限频为五分钟，事务与 FULL 同步保持；构造升级和云端替换仍显式备份。昵称预留通过 `007` 和注册/改名事务维护，NFKC、空白与小写归一后的 SHA-256 键唯一，失败回滚资料更新。前端移除排行 ID，增加透明面板、小屏操作与静态进度卡片。

## 1.1.0 成就、公开资料与界面响应

累计 AC 成就缩减为 1–2000 题的 12 档，500、750、1000、1500、2000 题奖励永久称号；连续训练 30、90、180、365、730 天同样奖励称号。旧累计 AC 3000/5000/10000、独立 AC 3000/10000 不再展示或新发奖励，连续 1000 天替换为两年 730 天。`achievement_xp_claims` 保留所有旧领取记录及其经验；新称号写入同一稳定领取键、`awarded_xp=0`，不引入第二套会重复奖励的账本。旧 1000 天领取记录可证明两年称号，不另补经验。

成长接口返回全部 `titles` 和自动佩戴的 `equippedTitles`，后者至多为最高 AC 和最高连续训练各一枚。成就提供 `rewardTitle`，旧奖励改为称号后以 `legacyAwardedXp` 保留历史说明。`account_preferences.ui.seenAchievements` 在保存和三方同步时取并集；打开成就弹窗不会批量已读，卡片鼠标经过或键盘聚焦才逐项确认。

本机 `TrainingService.public_progress()` 从同一成长证据派生公开摘要，包含 level、tier、rankTier、rankScore 和最多两枚称号；未解锁排位分为 null。复用近期成长计算，个人库改动、北京时间日期或公开账号资料改变使缓存失效，并有五秒上限反映定级变更。客户端通过认证资料接口上传摘要，服务端以 `006` 新表独立保存；排行榜 JOIN 小摘要，不读取或解压个人学习快照。公开 ID 与私有登录号分离；摘要不改变 AC 排名与结算。

比赛列表每页只渲染 40 场，搜索和排序后返回第一页。工作区响应未变时保留现有对象引用，减少无变化轮询造成的重渲染。窗口不可见时暂停常规界面数据和目标轮询，恢复可见时刷新；后台账号心跳、数据上传、任务执行和软件自动更新继续，保障会话检测与自动安装。这里描述的是实际减少的工作量，不承诺所有设备达到固定毫秒响应。

数学标题、Markdown 与讲义阅读器改为按需导入，构建主入口由 871.12 KB 降至 423.61 KB，另有 8.90 KB 首屏共享 JSX runtime；编辑器仍是约 560 KB 的按需模块。原生 WebView 主窗口取消无用途的请求头订阅，活跃/最小化分别使用 Normal/Low 内存目标，不执行 Suspend；隔离测试已验证最小化时草稿 POST 和 JS 定时器继续工作。具体测量范围见[1.1.0 记录](releases/1.1.0.md#响应与加载)。

成长页合并账号管理、CF/AtCoder 公开账号、翻译设置与获得称号；牛客和洛谷不再显示无数据的公开评分行。顶部段位框直接打开训练概览，每日任务独立提示。比赛“开始比赛”复用已有预览、题单完整性与模拟赛启动保护，未绕过进行中比赛和题面限制。

旧客户端的增量更新器不接受根目录新增构建信息。1.1.0 将权威 `BUILD-INFO.json`、`SOURCE-MANIFEST.json` 副本随已有白名单 `resources/` 路径交付，面向旧版的增量清单不声明这两个根路径。新版冻结程序启动时校验安装版本、40 位提交号与来源清单 SHA-256，再原子更新根目录副本；路径固定、大小有界，拒绝符号链接与 Windows junction，失败回滚并记录日志。个人数据不参与该迁移。新版更新器仅将这两个根文件加入后续升级白名单。

## 边界

背包 DP 在独立浏览器程序打磨后，现已接入开发源码，正式版待联合发布。`frontend/standalone/` 仍可将相同课程构建为内联 JS/CSS 的离线 HTML 和 ZIP；独立包进度保存在自身浏览器来源的 localStorage，不连接 TB API、账号同步或个人 SQLite。主应用使用已有账号偏好与训练入口，两种运行方式不自动混用各自的个人进度。构建及验证见[课程设计](algorithm-lab-design.md)。

`frontend/` 只负责界面、编辑器与交互，通过 JSON HTTP API 调用服务；不导入 Python 或读取归档文件。`backend/` 管理题库、个人记录、公开数据、翻译和本地评测，可以只启动 API。`desktop/` 创建 WebView2 工作台窗口，并通过 `external_browser.py` 操作可见浏览器的原站表单。`server/leaderboard/` 是独立部署的 Node.js 账号、学习数据同步与排行榜服务，共用同服务器的 MySQL。客户端 API 保留 Python，本轮没有改写为 Go。

开发入口：`python backend/backend.py --offline` 与 `frontend/npm run dev`。Vite 代理 `/api` 并保留会话令牌。若直接跨源连接，使用 `TB_FRONTEND_ORIGINS` 显式配置允许的来源，多个来源以逗号分隔；未配置时仍执行同源校验。API 只监听回环地址，写入要求 `X-TB-Token`。

## 数据与迁移

每日训练是完整个人记录的派生视图。`workspace.training` 保留全部活跃训练，新增 `today` 与 `lastActivityAt`：以北京时间判断当天加入、保存草稿、运行、提交或查看题解的活动；补题、样例待验证、7 天复习与 30 天抽检自动进入当天队列。v1.0.13 起不再强制生成独立重写队列，题解查看证据仍保留。跨日由工作台轮询刷新，不删除旧训练、提交或草稿。重新开始练习更新参与时刻，别名题合并当日活动。前端按任务紧迫程度分段显示，已完成且没有到期任务的题置底。

提交记录按同一北京时间日期分组，数据库保留每次运行和提交；v1.0.15 的全局历史仅查询正式提交，工作台继续显示样例运行。每日题数和 AC 数按不同题目去重，AC 仅计原站回执。翻页会合并同一天的记录，统计注明仅包含已加载的记录。列表、详情与工作台共用评测缩写，WA 红色、RE 紫色、CE 蓝色、TLE/MLE/OLE 橙色、AC 绿色；本地样例通过不改称 AC。

| 文件 | 内容 | 分发与升级 |
| --- | --- | --- |
| `data/library/` | 公共题目、题面、题解、讲义及精确关系（文本 JSON 源） | git 管理的可 diff 文本；首次启动或打包时重建 |
| `data/library.sqlite3` | 由文本源重建的二进制题库 | 随包分发，无个人进度；构建产物，不进入 git |
| `state/tb-library.sqlite3` | 可更新的题库工作副本、导入内容、抓取题面 | 首次合并内置库，后续按来源摘要合并；保护本地修改 |
| `state/tb-personal.sqlite3` | 训练、提交代码、草稿、模拟赛、身份、任务和经验 | 永不由安装包覆盖 |
| `state/accounts/<内部 ID>/tb-personal.sqlite3` | 切换到其他注册账号后的个人记录 | 与原工作区隔离；不覆盖已有记录 |
| 服务端 MySQL `account_state` / `account_login_days` | 账号权威学习快照、版本号、北京时间登录日期 | 1.0.20 增量迁移；与既有账号和排行共用数据库，禁止以空库替换 |
| `state/tb-documents.sqlite3` 及缓存子目录同名数据库 | 设置、加密翻译凭据、公开 HTTP 缓存、知识分析等 JSON 形状文档 | SQLite 事务写入；旧 JSON 只迁入一次 |
| `state/backups/` | 升级、导入前的 SQLite 在线备份 | 保留已提交 WAL 内容 |

`data/library/` 下是随包题库的文本源：`meta.json`、`problems.json`、`solutions.json`、`detailed_solutions.json`、`statements.json`、`lectures.json`、`links.json`。`data/library.sqlite3` 是构建产物，不被 git 跟踪：首次启动时若缺失会由 `backend/store.py` 自动重建，`scripts/build_release.py` 打包时同样保证重建，`scripts/check.py` 校验前也会补齐。维护者用 `python scripts/library_seed.py export` 从 sqlite 导出文本源，用 `python scripts/library_seed.py build` 重建 sqlite。内容升级按文本源指纹（`bundled_sha256`）判定，与 sqlite 文件字节无关。

`TB_STATE_DIR` 可覆盖状态目录，`TB_LIBRARY_DB` 可指定工作题库，`TB_ARCHIVE_ROOT` 指定显式导入/收件箱根目录，`TB_BACKUP_DIR` 可指定个人记录备份目录。默认状态在程序目录的 `state/`；Windows 安装到当前用户可写目录。

旧 JSON 文件保留字节不变，后续读写 SQLite。Windows API Key 仍使用用户绑定的 DPAPI 加密，不进入公共题库、响应或日志。0.5 个人数据库保留原有表和数据，由训练服务进行兼容升级。`--migrate-local` 只在用户选择旧安装导入时运行，复制允许的状态和设置；在线备份支持旧进程的已提交 WAL。升级安装不会重新导入另一份身份，也不会覆盖现有目标。

公共库升级按表记录上次分发内容的摘要。只有未在本机修改的内容随新版本更新；用户导入、修改和后来抓取的题面保留。事务失败回滚，外键与完整性检查拒绝损坏内容。新库与个人记录分开，卸载保留运行后产生的状态目录。

Markdown 是正文格式与交换格式，运行时不通过路径定位题解。`scripts/import_library.py` 和收件箱处理负责显式导入旧归档；旧源文件保留。收件箱在提交前校验章节、冲突和讲义，正文与引用关系一起入库。

## 内容加载

1.0.20 的题库紧凑响应减少重复字段，并按公共数据签名缓存已经序列化的响应字节；hub 不重复携带目标数据。题库 UTF-8 响应由约 12.68 MB 降至 7.98 MB，首屏 JavaScript 由约 1.419 MB 降至 0.863 MB，约 560 KB 的编辑器模块按需加载。这些是响应与构建体积，不代表所有设备的耗时承诺。

原站题面获取在有限并发的后台任务中执行；网络不持有个人训练锁，失败结果缓存 60 秒以免连续重试拖慢其他接口。统计历史与官方奖励重放按记录和已解题目线性处理，避免逐题重复扫描全历史。浏览器扩展空闲时按 30 秒间隔轮询。账号切换释放非当前训练服务、后台任务和缓存，防止曾登录账号长期驻留。

1.0.19 将公开题库快照保存在内存及 SQLite 文档缓存中。数据库文件与 WAL 变化、公开同步元数据、资源与程序版本决定缓存是否失效；调用方得到独立对象，缓存不保存会话令牌和个人训练。知识分析新增一题证据时，只重新编码该题。账号切换使用当前令牌，个人进度仍从当前账号数据库读取。

单题与工作台在一次调用内复用题库快照；讲义关系一次批量读取，题解存在性检查不读取正文与配图。前端仅合并同时进行的相同 GET，完成后的请求重新读取，任何写入都使后续请求进入新代次。没有长期缓存个人响应。

## 1.0.20 账号同步协议

`backend/account_sync.py` 白名单导出个人训练、练习与模拟赛、草稿、完整提交和原站证据、目标与每日分配、XP/每日/成就/排行奖励账本、排位解锁、账号偏好和个人题目事实；CF/AtCoder 公开绑定与资料也按账号迁移。服务端是权威版本，本机 SQLite 是可恢复的工作副本。站点 Cookie、浏览器会话、翻译密钥、DPAPI 密文、机器路径与设备设置不进入快照。

登录通过 `/v1/accounts/state` 读取快照，完成本地备份、合并和 CAS 版本确认后才公开已登录状态。初次迁移按主键去重，后续采用逐行摘要基线进行三方合并，识别编辑与删除；冲突版本留在 `account_sync_conflicts`。同一首通或成就领取键不能累加 XP，`achievement_xp_claims` 按稳定成就 ID 合并；缺少真实达成日期时允许 `unlocked_at` 为空。

持久化写入后后台聚合上传，普通 GET 不等待云端网络；数据库快照在本机锁内短暂读取，网络请求在锁外执行。同步状态暴露 pending/error/revision/lastSyncedAt，正常退出及更新使用等待屏障。独立后台心跳约每 3 秒验证会话，慢上传不阻塞会话失效检测；切换账号释放旧服务，避免多账号轮询。

每次登录在账号行锁内撤销旧会话；状态保存持有同一账号锁，并在事务内复验会话与 revision。旧设备迟到写入不能覆盖新设备。已有云端版本的账号拒绝不带 `X-TB-State-Protocol: 1` 的旧客户端，426 门槛在登录事务内复验。断网不能保证即时获知撤销，未上传记录保留到下次登录合并。

快照使用带 SHA-256 的 gzip/base64 封装，线上最大 4 MiB、客户端解压最大 64 MiB；服务保存有界压缩封装，不展开全部源码。大 JSON 在解析前限制结构数量与深度，避免密集小对象耗尽堆；大状态请求限并发，心跳保持独立。传输使用 HTTPS，压缩不提供端到端加密。

`account_problem_facts` 只采集本账号引用的题目，保存 `row`、`raw`、已缓存 `statement`，必要时附本机导入题 `solution` / `detailedSolution` 与可移植图片。引用 ID、题库签名或公开同步批次变化时更新；每次心跳不扫描整库。另一电脑没有公共 ID 时，训练和题面读取使用这些个人事实兜底，避免导入题的标题、代码或缓存题面消失。收藏等偏好保存在 `account_preferences`，按键和 `updated_at` 合并并保留冲突。

服务迁移使用 `005_account_state.sql` 增量建表与运行时切换脚本；先备份 MySQL，再升级服务，再分发客户端。2026-10-16 已完成生产备份、迁移、运行时切换及公网 HTTPS 健康检查，健康响应为 `version: 1.0.20`、`accountStateProtocol: 1`、`singleSession: true`。Caddy 仅对账号状态 PUT 放宽至 4 MiB，其余请求保留 64 KiB 上限。操作与回滚见[共享服务说明](../server/leaderboard/README.md#1020-同步上线)。

## 题解与讲义

0.10.10 起，每道题可以分别保存默认题解和详细题解。原 `solutions` 表及 `solutions.json` 保持原文；独立的 `detailed_solutions` 表和同名 JSON 文本源保存详细版，按题目 ID 关联。旧库升级到 schema 4 前执行 SQLite 在线备份，旧文本源缺少详细版文件时仍可构建。两版按各自分发摘要合并，分别保护用户导入或修改的内容。

`/api/solution` 保持原有 `markdown`、图片和基础讲解字段，增加可为空的 `detailedSolution`；两版共用规范化原题定位和模拟赛访问限制。阅读器每次打开先展示默认版，读者主动切换详细版；尚未收录时明确显示待补充，不用原文或自动摘要冒充详细内容。详细版完整呈现概念、样例推演、正确性与代码，不应用默认版的入门摘要折叠。

题目 ID 与原站规范化 URL 索引共同定位内容。同题不同 URL 写法可共用已收录的题解、题面和讲义。基础讲解关联分为本题自己的章节和明确引用；不按共享标签扩散。正文摘要用于去掉重复的关系，保留不同的推导。前端将正文中的从零讲章节折叠，按需展开。

题解和讲义的本地配图在显式导入时一并嵌入 SQLite，运行时不依赖原始 Markdown 或图片目录。支持 SVG、PNG、JPEG、GIF、WebP、AVIF、BMP；相对路径、中文文件名和 Markdown 引用式图片在导入时解析。外部 HTTP 图片保持原链接。题解页、讲义页和折叠讲义共享图片组件，可点击查看原尺寸，Esc 关闭并返回阅读位置。

内容版本升级替换未修改的内置讲义；旧讲义只有在没有关系引用且内容仍等于上次分发摘要时才清理，用户修改及自建引用保留。经审阅的图文稿保留原推导，讲义只补本题题意和应用位置，不重复套入通用基础模板。

## 外部接口

0.10.8 的普通本机请求可在同一账号内并发执行；登录、退出、密码和身份修改使用独占请求上下文，等待已有请求完成，随后切换工作区和令牌，避免跨账号响应或写入。后台凭据失效只撤销当前会话，不切换个人工作区。主界面等待题库和个人训练后即可显示；收件箱、公开同步和成长统计独立更新，失败保留上一份数据，并合并在途刷新。仅进行中的模拟赛启用每秒倒计时，题解正文和章节划分复用稳定结果。

`desktop/browser_preparation.py` 提供 `/api/browser-preparation` 的只读状态与受本机会话令牌保护的显式操作。缺少扩展或已知缺少原站登录时，提交返回准备提示，不调用原站提交器。界面统一说明安装、四站登录和重新检测，并在登录/验证提示时打开说明。扩展后台只读检查原站公开页面的登录标记；检查不阻塞 Cookie 同步、准备接口或提交，不改变已有权限。无法确认登录时返回 unknown，不当作已退出或绕过原站最终校验。状态仅包含枚举和扩展版本，不向前端返回 Cookie 或能力令牌。浏览器关闭时仍区分已安装扩展和已缓存的登录。操作只允许固定扩展目录、Edge/Chrome 扩展管理页与四个原站登录地址。

0.10.12 扩展对四个原有域名声明 HTTP 与 HTTPS Cookie 访问权限，提交和页面请求仍使用 HTTPS。Chromium 按 Cookie 的 Secure 属性构造权限检查 URL，仅有 HTTPS 权限会漏导出非 Secure 的登录 Cookie（包括 CF JSESSIONID），即使该 Cookie 正被 HTTPS 页面使用；实测与 [Chromium Cookie 权限过滤源码](https://github.com/chromium/chromium/blob/main/extensions/browser/api/cookies/cookies_helpers.cc) 一致。回归必须同时包含非 Secure、Secure 和第一方分区 Cookie，不得全部用 Secure 测试数据代替。

0.10.12 启动时与每三十秒检查全部四个平台，Cookie 变化立即触发刷新，登录状态不依赖原站标签页或浏览器窗口。扩展读取默认 Cookie 存储及各平台自己的 HTTPS 第一方分区（`hasCrossSiteAncestor=false`），同域、同路径、同名冲突优先原站顶层分区；不导入第三方嵌入分区。Chromium 默认 Cookie API 查询不含分区 Cookie，参见 [Cookie API](https://developer.chrome.com/docs/extensions/reference/api/cookies#partitioning)。AtCoder 按现有 Revel 会话的明确 `UserScreenName` 字段识别登录，不能仅凭存在 `REVEL_SESSION` 就认为已登录。已有页面仅以新的同源 GET 验证状态，不用旧登录页 DOM 覆盖当前会话。

## 软件自动更新

`backend/software_updates.py` 固定读取本项目 GitHub Releases 的最新正式版本。1.0.18 每次启动立即检查，与旧 `autoCheck` 偏好无关；该偏好只控制运行期间每 24 小时的额外检查。桌面宿主注册 launcher 后启用自动下载，失败间隔一分钟重试；同一进程重复 start 不产生重复任务。版本按三段数字比较，预发布不安装。仅接受指定仓库对应版本的更新资产、GitHub 返回的 SHA-256 和有界大小；下载跳转只允许 GitHub 的 HTTPS 资产主机。系统代理共享匿名查询额度耗尽（HTTP 403 且剩余额度为 0）时，尝试一次直接 HTTPS 查询。断网、限流与损坏文件均保留当前程序。

每日目标以各自 `goal_daily_assignments` 的题目计算当天完成数；按原题 URL 去重，同一天两个目标不重复分配同题。当天题量持久化，其他目标的 AC 不会清空这组任务。首次升级补回旧版错误清空的题单，并保留手动移除训练的操作；目标累计新题数仍沿用创建后的学习进度。

公开题面允许空样例输入以及没有样例，获取失败可重试并保留草稿。洛谷优先采用原站已公开的中文版本，英文题面仍可调用已配置的翻译服务。知识点元数据保留官方宽分类，对缺失旧题按精确 URL 合并公开标签和已复核的题面分析；后台同步会继续补充后续捕获的缺失知识点。

四站的已运行浏览器会话均可用于后台提交；没有浏览器窗口时保留原生静默流程。`needs_verification` 只显示本次提交的验证入口，不打开四账号登录面板。显式打开验证会话后保留对应浏览器标签，洛谷也能复用同题空编辑器页。原站已明确拒绝的验证错误只在用户再次点击提交时清除；未知受理状态或已取得提交编号时不自动重发。

每日经验任务按北京时间当天的不同题目官方 AC 计数，旧题当天重新 AC 可计入，反复提交同题仍只计一次；仅打开旧题和样例通过不计。基础首次 AC 经验和目标新题累计不重复发放，已领取奖励记录保留。可领取任务的提示点为导航右侧垂直居中的白点。

## 官网回执与完整比赛（1.0.15）

Codeforces 公开 user.status 每 15 秒按已配置账号读取终态回执；账号切换期间返回的数据丢弃。官网手动提交不依赖 TB 任务。浏览器扩展读取 AtCoder 本人提交页，并被动观察牛客、洛谷原站提交与评测响应，按扩展连接能力、平台和配置账号校验后写入 SQLite。以平台和提交编号去重，保留官网提交时间；没有源码的补录明确标识，不拿草稿冒充已提交代码。

原站实际要求验证时，切到浏览器预填代码，由用户使用原生表单提交，继续收取回执；准备慢或普通适配错误不自动转成人工提交；不会自动处理人机验证。提交页的手动改动只在原生提交事件或原站请求中捕获到时保存。

全局提交记录仅查询正式提交（排除运行和样例评测），工作区仍保留样例运行记录。今日 AC 按北京时间、当天不同原题去重；成长页总做题数累计已确认 AC，包括已配置公开账号在当前题库外的已知通过记录。

比赛的公开完整题单不受训练难度设置裁剪，重现赛检查题数和题面。比赛显示名集中规范化，内部题目身份保持不变。模拟赛删除使用 deleted_at 隐藏已结束记录，草稿、代码及 AC 数据保留；进行中比赛须先结束。

当已同步的远端题目被内置完整题单覆盖时，每日目标通过原题 URL 的身份映射继续识别旧题号、旧提交和当天固定题单；不得因可见题目编号改变而替换已完成任务。

## 1.0.16 成长与题库元数据

`backend/tb_rank.py` 统一递增经验曲线和排位派生规则。个人库 `tb_rank_profile` 只保存首次解锁时间；分数从原站 AC 证据按北京时间重放，避免重复刷新扣分或发分。每日维持可使用重复原题，首次加分按规范 URL 去重。未知、非独立或历史解锁前的通过不加排位分。题库补全保留公开来源和 LOW 估算区间；模型分类不冒充已验证算法。公共统计绑定只支持 CF/AtCoder，提交平台仍为四站。

CF 原始提交表单先异步 POST `data/problemLock`，回调启用原生 Submit 控件。代码填写与历史快照完成后等待该控件放行，最多 30 秒；等待期间保留原站验证与控件状态，发送代码前仍须宿主确认检查点。题目和语言值已正确时不触发 change，避免重新申请锁。原站表单核验只允许页面自己的权限/验证请求，代码提交请求被拦截，不建立真实测试提交。

## 1.0.17 分类、难度与活动

`ContestTabs` 与 `contestShelves.js` 为比赛和题库提供相同的七项分类。原有保存筛选中的平台条件仍可读取；点击分类会清除旧平台值，避免不可见条件叠加。比赛名称保留国家与站点，镜像重名时保存 `contestVariant`，不改题目 ID。

`scripts/audit_difficulties.py` 逐题产生带来源、区间和可信度的难度元数据。`difficulty.py` 保存牛客复核依据和保守统计粗估；知识分类不再生成缺少证据的默认难度。1.0.17 元数据在升级时替换旧估算缓存，后续明确未定级的结果也可清除旧猜测。估算只用于训练参考，不能作为原站官方 rating。

Codeforces Gym 来源通过公开列表和公开题单收录；仅采用 ICPC 规则的混合训练不归入历史比赛。新增条目保存原题 URL，题面按需缓存到工作题库；内置但带 `remote:` ID 的条目直接读取本地库和公开来源，不要求同步状态中重复存在该题。

活动接口的 `officialAccepted` 按北京时间日期、原题身份去重；已在前一天通过的题目今天重新通过仍计入今天。公开账号的题库外已知通过也参与日期计数。界面只展示此通过数，强度与最长连续均由所选年份的通过日期产生。

个人库 `official_first_xp_awards` 按规范原题身份保存已获得的首通经验，`official_xp_state` 标识迁移完成。旧安装在替换题库与难度缓存前保存原档位，首次迁移据此保留经验；缺少原数据时使用随包保存的 1.0.16 已发布奖励档位。这些资料只用于经验迁移，不影响当前难度、推荐或排名难度。新安装直接从当前难度记账，未定级题获得评级时只补发一次；重复读取不写入或重复备份。任务与排行榜奖励继续使用原有独立记录。


## 1.0.18 赛事策略与界面

`contest-policy.json` 保存 CF 普通赛白名单和已收录 Gym；`xcpc_discovery.py` 限额读取新题单，校验原名年份、结束状态和真实题目链接。已收录远端 Gym 参与去重，避免每次重复阻塞发现。`contest_policy.apply_visibility` 只把退役自动导入题标为 `catalogHidden`，旧题仍在私有库和个人接口中，公共选题、自动推荐与随机组卷排除它们。

`contest_translations.py` 与 `contest-event-metadata.json` 提供中文显示名和原赛日期。镜像时间不能覆盖已核实原赛时间；年份精度不伪造具体日期。整场 `contestDifficulty` 与单题 `difficulty` 独立，模拟赛中均隐藏。公共题库文本源保留原 ID，修改后的 raw 显式保存 `_id`，避免改名断开草稿与记录。

Goals 返回独立于单个目标的合并 `contestPlan`：同类比赛取最高题量和练习范围，给出排除已通过题的建议；每日分配表不重写。`hub/dismiss-all` 在锁内持久化已读，不删除通知。每日任务仍使用既有领取 API，在顶部弹窗展示；领取后焦点失去时 Esc 继续有效。

离线评级与知识快照保存来源及审计文件；原赛队伍统计为聚合值，不随包分发参赛者资料。官方整场难度、原站 rating、镜像换算、榜单估分与自动知识匹配分别标明，不互相冒充。

### 1.3.1 界面恢复与快捷键

主 WebView 的可见性只由原站覆盖层管理，资源策略在最小化时仅使用内存提示。`ProcessFailed` 的主渲染退出最多每分钟自动重载两次；持续失败提供原生恢复按钮，浏览器进程退出提示重开程序。前端渲染异常由 `AppRecovery` 保持可见恢复界面；WorkBench 的逐编辑本机草稿日志不清除。仅实际进程退出触发自动重载，GPU 重启与脚本无响应不自动重载。

`PageSearch` 把页面唯一搜索和筛选渲染到顶栏槽位。筛选菜单根据视口定位，其下拉选项浮层不会被外部点击处理提前关闭。快捷键集中在 `lib/shortcuts.js`，设置可覆盖默认绑定，编辑器与列表都读取同一账号偏好。后端只接受已知操作 ID 及受限文本，不执行绑定内容。
