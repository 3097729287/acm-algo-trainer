# 等级、经验与能力段位

## 1.3.0 连续练习与管理员

顶栏火焰以北京时间的正式提交日期计算连续练习，不要求 AC；运行样例、只存草稿和浏览不计入。正式原站历史回执可证明练习；今天未提交时保留昨天连续记录，隔过完整空缺日后归零。七档动画阈值为 1 / 2 / 4 / 7 / 15 / 30 / 60，60 天后大小固定。它与按原有规则发放经验、成就及能力证据的账本分别派生，不会因火焰动画而补发 XP。

段位与永久称号使用分级勋章。管理员工作区的手动等级、段位和成就授权只影响其私有显示与控制日志，不产生官方回执或公共排行证据。


本文对应 v1.2.1。王者门槛为 2200，原有能力分自动对应新段位，经验与记录保持原值。[发布与验证状态](releases/1.2.1.md)。

等级只取决于累计获得的经验。升到下一级需要 `200 × 当前等级` XP，延续原来前十级的经验曲线，最高 100 级。5 级累计需要 2,000 XP，并解锁能力段位。解锁之后仍按真实经验继续升级；不会将等级固定为 5 或 10，也不会把已有经验转换成排位分。到达等级上限后仍保留全部累计经验。

能力段位按已验证题目难度计算，不取决于 XP、累计刷题数或连续登录。定级至少需要 5 道不同原题的独立首次官方 AC：

- 只接受正式提交、原站 AC、已完成且具有真实受理时间的记录；本地样例运行与样例通过不算。
- 本机记录必须能证明首次 AC 前没有查看题解。公开同步历史中未知的独立完成情况不会被推测为独立。
- 难度必须已知且为有限正数；未来时间、未定级或无效难度不参与计算。
- 同一规范原题 URL 的别名与重复提交只算一题，以首次 AC 的独立完成证据为准。
- 解锁前已获得的有效证据继续参与定级，无须重复提交。

在有效题目中取难度最高的 5 题，以这 5 个难度的中位数作为能力分。少于 5 题时显示「定级中」。单独通过一道高难题不能直接提升到高段位，反复通过简单题也不能把中位数堆到高难度。能力分是题库训练尺度上的参考值，不等同于原站官方 rating；题库已有明确标注的估分也属于这一尺度。难度资料修订时按当前证据重新计算，不修改已经获得的 XP。

## 本机接口

`growth` 保留 `xp`、`totalXp`、`level`、`currentLevelXp`、`nextLevelXp`，新增 `levelCap: 100`、`rankUnlockLevel: 5`。`rankedEligible` 表示已解锁；`mode` 保留为 `xp`，不再意味着经验成长被排位替代。`levelName` 为 `Lv.N`。已定级时 `growth.tier`、`growth.badge` 对应能力段位；没有有效段位时 `badge` 为 `null`，`tier` 保留协议兼容的「黑铁」占位值，界面应依据解锁与定级状态显示中性外观。

已解锁的 `growth.ranked` 包含：

| 字段 | 含义 |
| --- | --- |
| `qualified` | 是否已取得至少 5 道有效证据 |
| `evidenceCount` / `minimumEvidence` | 当前有效题数 / 定级所需题数 5 |
| `abilityScore` | 能力分；定级中为 `null` |
| `tier` / `badge` / `title` | 能力段位、稳定样式编号与名称；定级中前两项为 `null` |
| `nextAbilityScore` | 下一段位最低能力分；最高段位或定级中为 `null` |
| `tierRequirements` | 全部段位的 `{tier, badge, minAbilityScore}` 列表 |
| `topDifficulties` | 用于计算中位数的至多 5 个难度 |
| `score` / `nextScore` | 为既有使用方保留的能力分 / 下一段位门槛别名；定级中 `score` 为 0 |
| `legacyPoints` | 旧版加分、维持与缺勤扣分算法的只读重放结果；不参与当前能力段位 |

旧 `tb_rank_profile.unlocked_at` 原样保留，没有新的个人数据表或破坏性迁移。旧版排位分原本按回执重放而非独立存储；该算法仍在 `legacyPoints` 提供，包括旧分数、累计获得与扣除分数。原有首通、任务、成就和排行榜 XP 账本、提交代码及草稿都不重写。新解锁时间使用现有事务和 SQLite 在线备份流程持久化。

## 同步与头像

1.3.2 起头像本级经验环从底部顺时针增长。知识雷达的掌握度是独立的个人作答估计，不参与段位和经验：解决率、独立完成、首次通过前的稳定性和难度表现分别占 50/20/15/15，题目按难度加权，跨标签去重。至少 5 道不同有效原站作答且其中 3 道有难度才显示百分比，否则为 `?%`；运行、样例和 CE 不补足样本，未练题不作分母。同步的公开 AC 可以证明通过，未取得源码时不据此声称独立完成。

公开成长协议仍为 1，只上传原来的五个字段：`level`、`tier`、`rankTier`、`rankScore`、`titles`。`level` 限于 1–100，已定级时 `rankScore` 使用能力分；未解锁或定级中继续使用 `rankTier: null, rankScore: null`。旧格式中缺少 `qualified` 的成长摘要仍可读取。服务端无需为此变更已有 SQL 字段。

头像保存在本账号私有偏好 `avatarData`，复用现有账号快照同步；不加入公开成长资料。点击右上角头像，在弹窗中选择 PNG、JPEG 或 WebP，界面在本机缩至 96px 内并压缩，也可恢复默认头像。保存接口只接受对应 Base64 data URL，整个字符串不超过 48 KiB，并校验编码与文件头。空字符串用于清除。文件路径、外部 URL、SVG 与其他类型被拒绝，私有资料不会包含选图路径。悬停或键盘聚焦头像查看本级 `经验值:X/Y`；段位提示单独显示能力分和下一段门槛。
