## 1.3.0 提交窗口与 Python

提交使用专用浏览器窗口。TB 取得并保存最终回执、把结果显示在工作台后，自动关闭本次窗口。登录、验证码、异常及结果尚未确认时保持可见，不自动关闭其他页面。

编辑器选择 Python 3 后，适配层只在真实语言控件中选择 Python 3 / PyPy 3，并触发原生 input/change 事件；没有相应语言时显示错误而不提交。C++17/20/23 的既有要求保持。浏览器管理登录、CSRF 与原生提交行为，账号测试使用拦截 fixture，不向真实 OJ 试交。


点击 TB 的“提交”，程序会打开可见的 Microsoft Edge 或 Google Chrome 原站提交页，准确选择当前题目与语言、填入代码，按这一次用户意图点击原生提交控件，再读取对应受理编号和最终判定。本地运行和样例测试继续在 TB 内完成；样例通过不等于原站 AC。

## 首次使用

1. 安装 Microsoft Edge 或 Google Chrome；TB 记住选用的浏览器，默认优先使用 Edge。
2. 在 TB 中打开题目并点击“提交”。首次使用时，在 **TB 打开的独立浏览器窗口** 登录对应竞赛平台。日常浏览器和提交浏览器分别保存登录状态。
3. 未登录时直接在弹出的原站页面自行登录；检测到本人登录后，TB 返回本题、填入代码并继续本次尚未发送的提交。验证码同样在原站完成。无需准备弹窗或再次点击提交；已经发送或被原站拒绝的请求不自动重发。
4. 受理编号出现后，TB 跟踪该次评测；窗口和标签页保持可见，可以核对原站结果。网络中断、标签页关闭或等待超时会提示“待核对”，不会用样例结果冒充回执。

无需安装浏览器扩展；旧版 TB 扩展可以停用。程序不再启动扩展会话同步或隐藏提交窗口。浏览器登录保存在本机独立配置，不复制日常配置的 Cookie，不上传到共享服务器，不随安装包分发。升级保留该配置。

## 记住原站账号

专用配置持续保存在本机；四站的一方 Cookie 另以 Windows DPAPI 密文写入本机 SQLite，关闭浏览器后重启会补回缺失的有效会话。Edge 与 Chrome 分别保存，网站退出后的空会话也保存。缓存最多保留三十天；原站已撤销或过期时仍需重新登录。

这些会话不读取自日常浏览器，不上传到 TB 共享服务，不随安装包或账号学习快照分发。升级保留现有浏览器配置。重现赛同样使用这条原站提交流程。

## 为什么使用独立配置

可见浏览器通过本机回环调试接口与 TB 的原站适配层连接。Chrome 从 136 起要求远程调试使用非默认用户数据目录；参见 [Chrome 官方说明](https://developer.chrome.com/blog/remote-debugging-port)。独立配置同时避免读取日常浏览器的其他账号和历史记录。直接打开一个普通浏览器标签页而没有这个连接，TB 无法自动填写和读取结果。

## 可维护的适配层

桌面启动入口只连接 `external_browser.py`，原站表单与结果解析由独立的 JS 适配脚本处理。保留原站语言控件、表单事件、CSRF 和验证流程；自动发送不重放旧 Cookie，也不使用旧的静默提交 API。已登录的原站页面仍可能因网站变化、维护或验证而暂时无法自动操作，此时请在可见页面核对；测试通过不代表真实账号已经提交成功。

洛谷代码编辑器可能晚于题目信息加载。TB 会等待编辑器可操作后再填入代码，兼容新版 CodeMirror 文档模型；等待时显示“正在等待洛谷代码编辑器加载，尚未发送代码”。登录与验证仍在原站完成。修复后的程序需要重新启动，已有草稿、提交记录和专用浏览器登录保留。

新版洛谷使用自定义语言菜单。TB 从真实菜单的当前语言识别 C++23 等兼容编译器；需要切换时点击该控件及其弹出的选项，再核对实际显示的语言。不会从题面中的编译器文字或其他菜单推断可用语言。C++98、C++03、C++14 不作为 C++17 及以上代码的可用选择。

浏览器及其登录状态归用户控制。仅在原站允许的训练场景使用；增加中间层不能替代原站规则或内容授权。

## 浏览器兼容与验证

1.4.0 使用新的 interactive 专用配置及非零本机端口，避免重连到旧启动方式的浏览器。端点必须属于本次启动的浏览器进程，后续按配置与 GUID 重连；旧配置不删除，现有 Windows 加密登录记忆继续恢复。登录网页跳到首页时，看到本人账号标记才返回本题，不能把页面上任意用户名当作登录成功。

Cloudflare 由原站运行，用户在可见浏览器完成验证。浏览器启动与登录恢复修复不能保证任意网络下的真实验证一定通过；网络、浏览器版本和站点策略仍可影响结果。[Cloudflare 支持环境](https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/)。测试只验证本机兼容性和拦截表单行为，不宣称真实账号验证或提交成功。


1.4.23 启动时按四个既有平台依次检查本人登录，缺失时才打开当前站登录页，完成后继续下一站。新增 CCPC 题目使用正常 `qoj.ac/problem/<id>`，在同一专用浏览器按需登录；不使用 UCup 团队账号域名或其他镜像提交，不新增第五个公开账号绑定字段。适配只操作本题原生提交表单、原生语言控件和事件，保持 CSRF 与验证码流程；测试使用隔离页面，不向真实原站提交。

QOJ 的 39 道新题保留原版 PDF 分页图，公式与配图不依赖有损文本提取，点击可放大；57 组样例另供复制和本地运行。这些原文 PDF 不显示为已经翻译的中文题面。部分分数只有在读到实际判题状态后才转换为失败类型，不能把任意数字或旧 AC 当作本次结果。
