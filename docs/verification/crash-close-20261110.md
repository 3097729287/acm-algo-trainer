# 1.6.15 异常窗口关闭验证

主界面 WebView 进程实际退出后，旧关闭协调器仍等待该网页的保存回调，导致首次关闭被取消，后续关闭一直被 requesting 状态阻止。本次将已确认的进程退出通知与原生关闭协调器连接，并让最终清理可安全重复执行。

14 项单元检查覆盖正常保存失败取消、成功关闭、异常页关闭、保存等待期间进程退出、迟到回调隔离、启动前关闭、GPU／慢脚本不被误当作永久故障，以及可选 SDK 日志属性读取异常。

隔离的真实 WebView2 使用私有测试资料目录，以 Browser.crash 触发 BrowserProcessExited：×、原生关闭按钮、保存等待期间崩溃三种情况分别约 5、16、53 毫秒完成退出，正常 finally 执行；合成 SQLite 已提交草稿内容保持原 SHA，没有伪造保存成功。另独立复核实际清理函数，单个资源首次异常不妨碍其它资源清理，finally 可重试失败项且不重复关闭成功项。

旧 WM_QUIT 退路仅在旧版隔离窗口验证，不是新版产品关闭流程，也未向用户当前健康窗口发送任何消息。历史浏览器退出原因没有足够证据归因于 OOM 或 GPU，本次不作该宣称。

本版不修改公共题库，不读取个人数据库或日常浏览器配置，不执行真实 OJ／模型请求。原始失败证据保留；结构化摘要见 [原生验证](crash-close-native-20261110.json)。打包与发布后的验证由发行回执单独记录。
