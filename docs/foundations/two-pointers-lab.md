# 双指针：每次移动都要有依据

双指针用两个位置描述候选范围、连续窗口，或已经读过与已经写好的部分。看见两个变量不意味着有优化；关键是证明可以丢掉哪些候选，并让位置总共只移动线性次数。

**相向。** 非递减数组 `[1,2,4,7]` 中找两个不同位置的和等于 6。开始看两端 1+7=8；固定 7，其他搭档只会更大，全部超出 6，因此放弃右端。随后 1+4=5 太小，1 已与当前最大搭档配过，更小搭档也不够，因此放弃左端。最后 2+4=6。这依赖有序性，与数字是否为正无关。若需连续段，排序会改变对象，不能直接这样处理。

**同向窗口。** 在非负数组中求和至少 S>0 的最短非空段。右扩加入一个数，和不减；左缩移走一个数，和不增。每次达标先记录长度，再尽量缩小。一旦不够，继续缩也不能达标。已丢弃左端点曾产生过记录过的合法长度，此后右扩只会使它对应的段更长，不会改善最短答案。

```cpp
int l = 0, answer = n + 1;
long long sum = 0;
for (int r = 0; r < n; ++r) {
    sum += a[r];
    while (sum >= S) {
        answer = min(answer, r - l + 1);
        sum -= a[l++];
    }
}
```

两个端点各至多前进 n 次，for 内虽有 while，总移动仍至多 2n，时间 O(n)。若每轮把右端重新设回左端，可能重复扫描成 O(n²)。如果窗口维护本身每步还扫描全段，也不能声称 O(n)。

负数破坏上面的单调理由：`[1,−1,5]`、S=5，原策略记录整段长度 3，移走 1 后和为 4 就停；但再移走 −1，和回升到 5，存在长度 1 的答案。因此原策略失效，前缀和的相消关系仍成立。若改问和恰好 K 的段数，可用前缀值频次匹配更早的 `P[r]−K`；这不等于已解决含负数的最短至少问题。

窗口还可以维护字符频次。求最长无重复段时，遇到重复就移走左端直到冲突消失，合法后记录最长；求最短全种类覆盖时，种类齐全后先记录最短，再移走左端。目标与合法条件不同，答案更新的时机就不同。

**快慢读写。** 原地去除 0，read 扫描原数，write 指向下一写入位置。保持 `[0,write)` 是 `[0,read)` 中所有非零数、顺序不变。write≤read，写回不会覆盖尚未读取的位置；结果只是 write 之前的部分，尾部旧值不算结果。O(n) 时间、O(1) 额外空间。

实现前先回答：指针描述什么？移动放弃什么、为什么安全？指针共走多少次？最后再检查 `l<r` 还是 `l<=r`、相等是否算合法、重复值按数值还是按位置计数。查找任意一对、数所有对、最长段与最短段，不共用一条未经证明的移动规则。
