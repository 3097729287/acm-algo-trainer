# 教学内容进度总结功能设计

需求确认日期：2026年11月5日。状态：需求已确认，待实现。

本功能统一主线任务、下一步推荐与周计划，根据当前用户的学习证据，给出完整、精简的规划文章。用户应能直接看懂当前阶段、最近进步、主要缺口、本周安排、下一阶段要求、预计所需时间和检验方法，并从说明中进入具体学习任务。

## 使用范围与目标

覆盖零基础、系统学习、训练遇到瓶颈和比赛备战等阶段。主要服务区域赛拿牌，也支持用户选择其他目标。每天学习前、安排一周训练、遇到困难时均可使用。

- 同时保留一个总目标；用户未设置时，按区域赛铜牌规划。
- 目标由类型、具体要求和可选截止日期组合，例如 ICPC／CCPC 奖牌、CF 分数、蓝桥杯奖项、专题学习要求。不同目标有不同路线、任务侧重和说明。
- 无截止日期时按可用时间持续推进；有日期时结合剩余时间安排。
- 一个目标下可同时推进多条学习主线。每条主线分别记录进度、缺口、阶段检验与预计周期，共用时间预算。
- 系统可以主动提出并行学习方案；用户采纳后开启。新增主线时显著展示时间重新分配、优先顺序与周期变化。
- 同时提供整体规划与当前专题总结。整体规划解释各主线的关系和取舍。
- 了解用户是否有队伍及承担的职责；用户明确选择团队备赛后，才加入团队训练安排。此阶段先记录当前用户的表现。
- 三账号在线组队、共享比赛与代码控制权另开一轮设计，不纳入本功能实现范围。

## 文章与表格的职责

页面主体始终是一篇完整、连贯的规划文章。简略模式保留完整规划逻辑并压缩措辞；详细模式展开依据、选择理由、路线和执行细节。语气可由用户选择，事实、阶段判断和任务不会因语气改变。

文章的主要顺序为：当前阶段、最近进步、主要缺口、本周安排、现在最该做的一件事。正文也须交代下一阶段是什么、为什么这样推进、预计时间范围及达标检验。

表格辅助呈现每天的任务、顺序、预计用时、完成状态和进度；图示用于表达阶段路线与知识关系。整体规划不能退化为一组表格或零散提示。关键判断在正文直接说明依据；证据不足时使用“可能”“尚未验证”等准确表述。

课程、章节、模板操作、实验室、题目、复习和综合训练均应有实际可用的跳转入口。详细依据可以查看对应记录，任务名称对应真实内容。

## 学习阶段与证据

总体路线采用“基础编码、常用算法与实现、专题应用、混合限时运用、区域赛模拟与查缺”。用户从证据支持的位置进入；各专题的状态可不同。

专题学习区分以下状态，分别核对相应证据：

| 状态 | 主要说明 |
| --- | --- |
| 接触过 | 有实际接触记录，尚不能据此判定理解 |
| 理解原理 | 能通过概念或适用条件检查 |
| 能跟着实现 | 跟做或操作练习完成 |
| 能独立实现 | 脱离示例完成实现检查 |
| 能独立用来解题 | 在未做过的题中独立应用 |
| 隔一段时间仍能完成 | 通过隔日等延迟检验 |

综合应用还要通过不提示算法类别的混合任务验证，作为进入相应下一阶段的依据。单次完成、长期保持和综合迁移分别记录。

主要依据为独立原站 AC、比赛表现、有效学习时长、模板练习、实验室跟做、复习结果。手动标记已读只产生有限影响，需要核实是否学会。学习时长用于判断投入、估计节奏与任务量，不能单独提升掌握阶段。

作答稳定性与能力判断沿用现有评估。一次通过与多次修改后通过可产生不同的稳定性证据；本功能不另行改写现有能力分、知识掌握度算法。

个人外部学习历史自动检测范围为 Codeforces、AtCoder、牛客、洛谷，不增加其他平台的个人历史补录。公开历史能证明通过，但独立性可能未知；利用它定位合适阶段，再以少量练习验证，避免老用户从头补基础。

用户自述已经会了或认为判断不准确时，提供验证机会。软件内的题解、提示和相关学习材料访问记录用于判断辅助情况；通过说明打开当前题所需的模板、讲解或提示后完成，应标记本轮辅助完成。仅阅读个人进度、周安排不因此标记辅助。

没有历史和足够证据的新用户按入门路线开始。长时间没有新证据时保留已学事实，先安排少量复习检查；出现困难后再确认一次，再决定补充内容。近期证据窗口之外的历史不能被解释为从未学过。

## 诊断与困难交互

重点覆盖旧知识遗忘、专题理解不足、实现不熟和比赛经验不足，也允许定位题意理解、思路、复杂度、边界处理、时间分配等问题。系统无法从结果确定原因时先询问用户。

同时支持主动点击“遇到困难”和明显停滞后的显眼提示。数日没有推进时先问情况；单次无操作停留由计时规则处理，不直接调整学习方向。

采用少量按钮、分层选项和设置完成交互，覆盖以下常见问题，并在需要时继续细分：

- 题意没理解、没有思路、知道方法但写不出。
- 代码出错、旧知识忘了、任务安排不合适。
- 任务太简单或太难、不知道怎样检验、学习后仍不会做题。

诊断可用短问答、实现操作、代表题。额外诊断通常控制在每周可用学习时间的10%以内，可按实际需要合理调整；正常练习、复习与每周综合训练不属于这项额外诊断预算。

遇到瓶颈先询问原因，提出调整理由和方案，等待用户采纳。系统不能仅因卡住就直接替换任务。阶段预计时间使用范围；证据不足时先诊断，再估算。

## 有效学习时长

鼠标操作、键盘输入、滚动、触控等有效学习交互均计入活动判断。连续五分钟没有有效操作时暂停计时，扣除整个连续无操作区间；恢复操作后自动继续。此前有效学习时长保留。

例如10:00发生最后一次有效操作，10:05仍无操作，此时扣除10:00至10:05；10:07恢复操作，10:00至10:07均不计入学习时长。输入代码期间持续敲键盘，即使鼠标不动也不触发暂停。

有效时长采用统一口径，避免把已扣除的停留时间继续当作学习投入证据。并发页面和重复回执不能重复累计同一时间段。

## 周计划与时间安排

按北京时间周一至周日的自然周安排。允许分别填写工作日、周末时间并设置休息日；首次没有时间配置时先询问，不猜测时间预算。此后每周第一次使用时可确认或一键沿用；未回应则沿用已有配置。

每项任务说明内容、执行顺序、预计用时、计划日期和完成条件。时间范围结合实际表现修正，避免只按题量推算。

| 规则 | 执行要求 |
| --- | --- |
| 优先顺序 | 进行中的比赛先继续；平时优先到期复习，其余按紧急程度、当前缺口和已采纳主线安排 |
| 多主线 | 分配共享总时间，说明各自推进节奏；新增主线时重新估算各自周期 |
| 每周综合训练 | 至少一次，覆盖各主线本周学习内容，独立计时，复盘与补题也占计划时间 |
| 时间很少 | 缩小为短综合检查，适应周末才开始或剩余时间很少的情况 |
| 未完成任务 | 按已确定的优先级顺延，占用后续相应预算，新内容相应后移 |
| 手动额外学习 | 不挤占或修改主线预算；其完成事实仍可补充证据，命中计划任务时自动记录完成 |
| 用户调整 | 支持换题、推迟、调整时间、选择专题和休息日，重组受影响部分 |

任务完成条件按类型区分：阅读、理解检查、操作练习、独立原站通过、空白重写、限时训练与复盘使用各自的真实完成证据。样例通过不能替代正式 AC，翻页或已读不能替代阶段达标。

限时综合检验期间沿用比赛中的说明边界，保留已有整体规划，当场题目的专题跟随与方法提示在交卷后恢复，以保留无算法提示检验的意义。

整周任务提前加入“我的训练”，按日期区分；课程、模板、实验室与综合训练同样可执行。相同原题和重复任务按身份合并，进入优先级最高的对应栏目，保留其关联目的与证据，避免重复安排。

## 自动执行与采纳边界

学习事实和任务安排分开处理。事实更新可以自动修正说明；新的阶段、方向或并行主线须通过方案采纳进入执行。

| 事件 | 执行方式 |
| --- | --- |
| 当前任务完成或出现新证据 | 自动更新完成事实及受影响说明，保持阅读位置 |
| 同一阶段的下周计划 | 按既定规则自动安排并加入任务 |
| 普通任务未完成 | 在已确定规则与预算内顺延 |
| 用户主动调整时间、专题、休息日等 | 按操作意图立即重组受影响部分 |
| 当前阶段达标 | 更新已达标事实，展示下一阶段方案；采纳后启动下一阶段任务 |
| 系统建议新增并行主线 | 展示时间分配、周期变化和理由；采纳后开启 |
| 明显偏差需要重新规划 | 先说明原因；涉及瓶颈时先询问，采纳调整后应用 |
| 正在限时比赛 | 保留已有说明，本场表现分析、缺口判断和重新规划在交卷后更新 |

未采纳新阶段方案时保留学习事实与既有可执行内容，允许继续复习、调整方案或选择其他专题。达到技能阶段条件与完成最终目标分开记录；区域赛拿牌目标以真实比赛结果作为完成条件，参赛前展示备赛进度。

## 入口与阅读交互

- 顶栏入口位于用户截图中书本图标左侧的红框位置。
- 支持像单题一样全屏显示，以及可拖动、缩放、置顶、收起为标题条的浮窗。
- 置顶仅在 ToBe 内生效；ToBe 最小化或切到其他软件时，浮窗不独立留在屏幕上。
- 记住上次全屏／浮窗方式、浮窗位置和大小、文章滚动位置与展开状态。
- 点击文章任务进入学习时，已置顶浮窗保持可用。
- 单题工具栏提供入口，也提供快捷键，沿用现有快捷键配置机制。
- 默认跟随当前学习内容，并提供“跟随当前内容”开关。整体规划始终可访问。
- 题目关联多个专题或已开多条主线时，优先跟随当前正在学习、选中的主线，其他相关专题可切换；无匹配时列出相关专题供选择。

新证据到达后在后台更新对应结论，保持阅读位置与展开状态。涉及较大变化时提示“说明有更新”；刷新后特殊显示更新段落。鼠标移到哪一段就清除哪一段的特殊显示，其他段落保留；关闭重开后，尚未查看的更新继续提示。

## 历史与离线

周结束、阶段完成、接受重新规划时保存历史快照；普通细节更新更新当前版本。历史可以回看当时的判断、安排和调整原因，允许删除。

删除历史仅删除相应文章和当时计划快照，实际学习、提交、代码、复习记录继续保留。当前文章、计划、未查看提示和历史按账号隔离，沿用项目既有持久化与同步机制。

打开尽快显示已保存内容，统计、同步、补题在后台处理，局部更新避免整篇重建。断网显示最近一篇。在线 AI 不是必需条件，核心判断、任务与解释由学习事实、知识关联和明确规则支持。

## 所需题目的补充

选题优先使用符合要求的现有内容。资料缺失或适合的题目数量不足时，功能负责补齐可执行的训练材料，不能长期停留在“题目不够”的提示。

计划题至少具备完整题面、限制、样例、实际评测入口、知识点与难度依据。中文译文、内置题解按已有资源使用，不作为本次确认的额外硬性入选条件。知识点、难度及其依据保留真实来源与性质，未知项继续待核实。

个人历史检测的四站范围不限制教学来源；可以使用 QOJ 等现有区域赛来源。补充采用真实原题与来源资料，明确原题身份、附件和版本，校验合格后提供给其他用户的公共题库。个人说明、计划、代码和进度仍属于对应账号。

具体补充方式由实现选择，优先复用现有原站获取、缓存、校验与公共内容更新渠道，后台补齐。暂未达到可执行标准的材料明确标识准备状态；不能伪造正文、标签、难度或完成事实。补齐功能与停开的大批量题解、全库翻译任务分开，不因此重启那些批次。

## 文章示例

以下使用虚构学习记录：目标为区域赛铜牌，工作日每日一小时，周末每日两小时；二分和 BFS 两条主线均已采纳。二分完成跟做和一道独立题，用户已确认边界条件不熟；BFS 完成跟做，尚无独立实现验证。

> 你目前处在常用算法与实现阶段。本周二分已从跟做推进到独立通过一道题，BFS 完成跟做，两条主线进度不同。
>
> 当前需要补的是二分边界判断和 BFS 的独立实现；隔日保持、混合题中的方法识别仍待验证。
>
> 本周给二分三小时、BFS 两小时，其余用于到期复习、综合训练与复盘，并留一小时余量。先处理到期复习，再通过短诊断定位边界问题；二分接着做独立变式与隔日重写，BFS 练习脱离示例实现。周末用一次无算法提示的综合训练检验本周所学。
>
> 下一步要验证二分能否隔日独立完成，以及 BFS 能否独立实现并用于未做过的题。诊断后再给出所需时间范围。今天先完成到期复习，再进入对应练习。

文章中穿插可点击的日程表、进度与依据。示例的周时间分配为：

| 内容 | 每周时间 |
| --- | ---: |
| 二分 | 3小时 |
| BFS | 2小时 |
| 到期复习 | 1.5小时 |
| 综合训练与复盘 | 1.5小时 |
| 余量 | 1小时 |
| 合计 | 9小时 |

例如某个工作日安排到期复习15分钟、边界诊断5分钟、独立练习30分钟，共50分钟，保留10分钟余量。正式计划以实际章节、题名、预计用时与完成条件呈现。

## 验收案例

| 场景 | 必须达到的结果 |
| --- | --- |
| 新用户未填写时间 | 先询问时间；默认区域赛铜牌与入门方向，不猜测日程量 |
| 老用户有可信历史或已有掌握证据 | 从适合的位置验证、接续；不能反复要求补已掌握基础 |
| 只有已读、翻页或长时间停留 | 不因此认定已掌握、可独立解题或阶段达标 |
| 一次 AC 与多次修改后 AC | 沿用现有稳定性判断，不另写一套能力分算法 |
| 同一原题跨平台或别名重复 | 合并证据与计划任务，不重复计题、排题 |
| 从说明进入当前题相关模板或提示后通过 | 标记本轮辅助完成，后续独立验证另记 |
| 自述已会或长时间未练 | 先给短验证；遗忘判断经检查和再次确认后再补充 |
| 诊断与正常练习并存 | 额外诊断通常不超周可用时间10%；综合训练及正常学习另计 |
| 键盘持续输入、鼠标不动 | 继续有效计时 |
| 连续五分钟无有效操作 | 暂停并扣除整个无操作区间；恢复后继续 |
| 到期复习与新专题冲突 | 到期复习优先，剩余任务适配预算 |
| 周末才开始或仅剩很少时间 | 仍安排短综合检查，复盘和补题计入可用时间 |
| 系统建议新增并行主线 | 显著显示时间和周期影响，采纳后执行；多主线共享总预算 |
| 同阶段跨周 | 自动按既定规则续排；阶段切换仍等待采纳 |
| 卡住或需要明显重排 | 先询问情况并解释理由，采纳后应用 |
| 用户手动额外学习 | 不挤占主线预算；证据有效，命中计划任务时记录完成 |
| 未完成任务积压 | 按优先级顺延，控制总量；不能把欠账全部堆到次日 |
| 一道题关联多条已开主线 | 默认跟随当前学习主线，可切换其他专题，整体规划可返回 |
| 阅读时收到更新 | 阅读位置和展开状态保留；刷新后按段提示，悬停逐段清除，未查看项跨次保留 |
| 浮窗跨板块、进入单题或最小化 | 在 ToBe 内保持独立操作；最小化后不成为桌面常驻窗口 |
| 正在限时比赛 | 本场分析交卷后更新，比赛中保留已有说明 |
| 合适题目不足 | 后台补充真实题目与必需资料，校验后共享；不伪造可执行任务 |
| 删除一份历史总结 | 实际学习、提交、代码、复习记录完整保留 |
| 断网打开 | 尽快显示最近保存的一篇，无需等待在线 AI 或原站同步 |
| 阅读整体规划 | 有完整文章、具体安排与检验方法，语言精简、表格直观，解释为何这样安排 |

## 实现时的统一约束

主线、下一步推荐、周计划与文章共用同一份已采纳计划和学习事实。当前文章、待采纳方案、已采纳计划和历史快照分别表达，避免把新事实更新误当作已经采纳新方向。

能力评估、正式提交与已有学习记录继续使用原有真实依据。新增计划和阅读状态沿用现有账号、SQLite 与同步机制；账号切换、迟到更新、离线重连和重复回执均按实际归属与版本处理。

相关现状可参阅[学习推荐](learning-recommendations.md)、[动态复习](adaptive-reviews.md)、[架构](architecture.md)。本文件描述待实现的目标行为；既有文档中与本次确认冲突的旧行为，在实现本功能时按本设计调整。
