# 算法实验室的创作与更新流程

适用：新课程、跟做题、相关详细题解及后续修订。用户于 2026-10-22 明确要求长期遵循。教学措辞同时遵守 [基本规范与错误复盘](algorithm-lab-design.md)，工具基础课与配图同时遵守 [题解教学要求](editorial-teaching-standard.md)。

## 交付什么

一个算法包含“学算法”和“跟着做题”两部分。当前只展示背包 DP，其余未完成算法从目录移除；不删除已有题库、历史作答或其他专题偏好。翻页图标放在始终可见的顶部，页底不重复导航。

“学算法”交代动机、状态、最小问题、正确性、转移、初始化、计算顺序和边界。“跟着做题”默认精选 5 道，由容易识别的模型逐步走向变形；每题分析完成后，交给用户独立实现完整程序。课堂操作、自评和勾选不能冒充原站通过。

## 1. 先列读者卡点，再写内容

- 写清先修知识、当前问题、每个量的含义与约束。不能把作者已知的关系省略为一句结论。
- 每个画面只解决一个主要问题。文字只保留条件、因果和必要过渡；删除口号、重复标题、重复进度与同义复述。
- 先给具体数据与合法方案，再给符号。递推必须展示由题意直接确定的起点；优化必须说明保留了哪些信息。
- 独立子问题、计算顺序、实际操作和最终方案分别命名。对背包，允许 A/B、处理 B、已选择 A 都是不同概念。

## 2. 核对精选题

逐题记录原站 URL、题号、完整条件、输入输出、范围和样例。评级来自可核实来源；不能把估算说成官方 rating。新增题解限已核实难度 ≤2200，包含 2200；未知先核验，已有任何难度内容均保留。

五题应各有一个明确的新思考点，避免只改数字。背包本轮选取 P1048、P1049、P1060、P2392、P1507，分别练习资源映射、目标转换、收益定义、平衡分组、两个独立资源。五题的洛谷官方难度均为普及−，不虚构它们具有不同评级。

新题使用稳定题号入公共 SQLite 文本源，原题面与结构化样例可在工作台离线读取。来源分组是教学题单，不伪造比赛经历或正式通过。已有同 URL 先复用原身份。

## 3. 逐题设计主动思考

按题目需要组合以下形式，不能把所有题写成点击灯泡、展开答案：

| 要解决的卡点 | 可选方法 | 必须看到的结果 |
| --- | --- | --- |
| 不知道从题面何处入手 | 选择并高亮关键条件 | 条件如何约束状态与选择次数 |
| 猜想未经验证 | 自选组合、双边分配、双资源实验 | 实际消耗、收益与是否合法 |
| 会看动画但不会算 | 先预测一个格子，再核对 | 完整来源与数值计算 |
| 公式和代码脱节 | 补关键转移，可按需对照参考行 | 变量、来源、收益和循环顺序的关系 |
| 样例过了却无法排错 | 极小反例、模拟错误代码、查首次偏离 | 错误发生在哪一步、如何修复和复测 |
| 只会套这一题 | 自解释、换条件追问、隔题回想 | 用户能复述识别信号和失效条件 |
| 缺少独立编码经历 | 实现交接卡与边界测试表 | 用户进入工作台，自行写完整程序 |

交互必须服务推理，不以点击次数凑进度。提示按需出现，关键定义和必要因果保持可见。允许跳转和重试，不强迫按作者预想的操作顺序装包。随着题目推进，减少直接给出的答案，让用户解释条件与模型的关系。

完整实现不在跟做环节默认抄给用户；参考的关键行不能宣称等于完整程序编译通过。正式代码编译与原站提交沿用工作台，跟做记录只保存草稿、推演、说明与自检。

进入过转移指导或查错环节后交接工作台，沿用题解辅助记录；直接跳去独立实现不凭空添加指导证据。跟做进度、自检勾选不产生 AC，也不覆盖历史独立提交。

## 4. 同步相关详细题解

先按算法标签、正文和实际代码审计覆盖范围，排除仅被顺带提及的情况。记录符合范围、超出难度范围、待核实及同源别名；按唯一原题写内容，同步保留其已有别名访问。

逐题选择真正有用的部分，不机械贴同一套标题或段落：

- 题面哪些条件提示了这个算法？为什么一个直觉做法不成立？
- 与实验室最基础版本相比，目标、状态维度、使用次数、可达性或依赖关系变了什么？
- 怎样从变化推出初始化、转移、顺序和答案位置？
- 哪个极小输入能暴露本题特有的错误？怎样定位首次错误、修复后怎样复测？
- 下次怎样识别相同结构，哪些条件变化后不能继续套用？

正文已有解释的地方不重复展开。补充内容应提供新的桥梁或反例；计数、最小值、树上分组、完全背包不能一概解释成 0/1 最大价值。更新前备份，保留旧正文、代码、图和来源；修改采用公共库文本源，不回写用户个人数据库或未授权的原始归档。

## 5. 验证与发布

1. 独立枚举核对教学小例；实际编译 C++，运行原题样例与针对性小数据。新增反例也要核对，不能凭文字显得合理就收录。
2. 验证错误输入、修改后的旧评语、章节跳转、自由重试、草稿恢复与工作台交接。跟做遵守模拟赛题解锁，同原题别名也应锁定。参考行的检查仅验证它实际支持的表达形式，不称为任意 C++ 评测。
3. 检查主应用及独立包的深浅主题、键盘、窄屏和长页导航；图和表达式逐项对应，来源、增量、写回及读写前后均有文字含义。
4. 对照原题库核对旧记录、正文、代码与图片均保留。库统计、README、用法、架构、主页、版本和发布记录与实际构建一致。
5. 多会话联合更新时，先确认双方要求均已完成，再按身份合并公共内容、重建库并统一验证；不能把文件短暂停写、会话结束或 task_complete 事件当作需求已完成。若最终说明仍列出未完成工作，继续按待完成处理。发布须来自已经推送且来源固定的提交，保留安装与升级验证、个人数据在线备份及哈希清单。

测试通过说明软件按设计运行，不等于新手已理解。每次反馈优先修复造成误解的推理链，并把新发现的写作约束补回本流程。
