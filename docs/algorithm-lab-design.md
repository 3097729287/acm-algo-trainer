# 算法实验室：教学设计与实现约定

状态：2026-10-22 实验性实现，首个专题为背包 DP。正式发布版本仍为 1.3.3；此课程属于开发源码，尚未进入正式安装包。

## 产品目的

把原“题单”升级为“算法实验室”。题目是引发思考和验证理解的工具，最终交付物是一条能教会人的学习过程。面向没学过当前算法的同学，默认教学语言为 C++17。背包 DP 不要求先学动态规划，但编写完整程序需要读懂变量、数组、循环和基本输入输出；初次接触 C++ 的同学可先完成直观实验。

用户的原始要求归纳为：

- 各算法专题按参考难度由低到高排列；同难度保留稳定顺序，未知难度置后，绝不编造评级。
- 以问题驱动，从核心思想开始；再建立模型、实现模板、练习、迁移和排错。
- 用户要主动做决定、输入、预测和解释，不能只被动阅读。
- 可以采用动画、小游戏、动图、可交互图、代码执行轨迹等不同形式；每种形式都应解决具体的理解障碍。
- 完成后，要能从新题的条件中想到算法，有入手点，能实现，也能检查错误。
- 教学不等于把几道模板题按难度排好，更不能把阅读打勾当作已经掌握。
- 首个专题以背包 DP 进行自由实验；总结出可复用方法，供未来其它算法专题使用。

## “教会”的可观察标准

| 能力 | 可观察行为 | 不能替代它的行为 |
| --- | --- | --- |
| 理解动机 | 举出朴素方法的瓶颈或贪心的反例 | 背出算法名称 |
| 定义模型 | 说清资源、选择、次数、目标和规模 | 看见题目标签 |
| 理解状态 | 用自然语言解释下标、合法性和一个具体格子 | 抄递推式 |
| 推导转移 | 解释每个候选从哪来、为何覆盖全部方案 | 记住代码长相 |
| 实现 | 从定义推出初始化、顺序、边界和答案位置 | 复制后跑通一个样例 |
| 排错 | 手造小输入，找到第一处不合法的转移并复测 | 随机改代码 |
| 迁移 | 在未展示标签的新情境中识别适用或不适用条件 | 只会相同题面换数字 |

课堂检验记录表示“完成过对应自测”，不宣称已掌握，也不写入 XP、AC、段位或知识雷达。真正的原站通过、独立性和提交稳定性沿用训练系统的证据。

## 通用课程蓝图

采用下面的认知顺序，章节数和表现形式可根据算法调整，不机械套五个标签。

1. **遇到问题**：给一个不需要算法术语也能尝试的小任务。明确输入、限制、合法方案和优化目标。
2. **做出选择**：先让用户按直觉行动，立即反馈操作的结果。
3. **制造认知冲突**：用最小反例击破一个常见但不成立的想法；解释它为何失败，而不只宣布正确答案。
4. **共同发明方法**：从朴素枚举找重复或单调性等结构，解释为什么留下的信息足够。不提前要求用户接受公式。
5. **观察与预测**：允许改变数据、回退、单步和播放；同时呈现代码、状态、来源和当前动作。先预测，再揭晓关键结果。
6. **连接代码**：每个关键代码决定都对应一个已讲明的理由。提供完整 C++17 程序和输入格式，注明复杂度、数值范围和适用条件。
7. **有扶手的练习**：先直接应用，再改变一个条件。按需逐层提示，最后才展示完整思路。
8. **拆掉扶手**：换题面、混入不适用情形、加入规模变化，练习主动辨认和选择算法。
9. **排错与复盘**：将典型错误和能够暴露它的极小输入配对。修复后必须复测。
10. **走向真实任务**：进入现有做题工作台独立实现和正式练习。自测与正式记录保持各自含义。

全程允许自由跳转，不因答错锁住后续内容。推荐路线和待检验位置应明确可见。对“尚未讲到”的概念，要给出桥梁解释或标为后续拓展。

## 交互形式如何选择

| 读者的卡点 | 合适的交互 | 必须呈现的信息 |
| --- | --- | --- |
| 不明白要优化什么 | 小游戏、操作任务 | 约束、当前结果、是否有效 |
| 总觉得贪心没问题 | 可重试的反例 | 直觉选法与更好组合的具体差别 |
| 状态下标抽象 | 点选表格或图节点 | 自然语言定义、当前格、来源格 |
| 原地更新读不懂 | 执行器、时间版本标记 | 更新前后的值、读到哪一轮、物品来源 |
| 不知道如何写模板 | 代码拼装、关键行填空 | 每个选项对应的语义、多个反例结果 |
| 样例过了但总 WA | 缩小数据的找错实验 | 应得、实际、第一处错误、修复后结果 |
| 新题里认不出来 | 隐去标签的情境判断 | 条件差异、适用性和第一步模型 |

动画只负责解释变化，不能替代解释。提供暂停、单步、回退、重置与速度控制；不自动开始播放。切换章节卸载计时器，窗口隐藏时暂停。减少动态效果设置关闭过渡，但保留手动推演。颜色之外还应有文字和形状标记；键盘、窄屏、深浅主题均可使用。

## 反馈与提示

题目至少提供三种层次的帮助：提醒关注的条件、指出推理方向、展示完整推导。每次只展开用户要求的下一层；用户不必先连续答错才能获得提示。非常短的操作任务可只用两层。

反馈针对当前选择，例如“这个状态把容量上限误当成必须装满”，而不是笼统的“错误”。正确反馈也要给理由。作答修改后清除当次评语；历史通过可保留为“曾通过”，不假装它代表当前选项正确。自动保存章节、输入、提示展开和课堂检验；重开后可继续。

练习阶段必须先允许用户独立思考。完整推导藏在最后一级提示；不能一边要求预测，一边直接显示被预测的结果。执行轨迹用于解释已有算法，不假装运行用户输入的任意 C++ 源码。

## 背包 DP 首课

完整主线是“不超过容量、每件最多一次、最大价值”的 0/1 背包。恰好装满、完全背包、换目标和规模不适用作为边界与迁移介绍；不宣称本课覆盖全部背包变体。

| 章节 | 核心问题 | 实现形式 | 检验 |
| --- | --- | --- | --- |
| 先装一次背包 | 为什么局部最好的物品会选错？ | 4 格背包、三件装备、即时容量与价值 | 找到最优组合；解释贪心失败 |
| 一起发明状态 | 哪些小问题可以只算一次？ | 二维表点选、选/不选来源、缺格预测 | 解释 f[2][4]；算出最后一格 |
| 看清循环的时间 | 为什么 0/1 背包要倒序？ | 一维执行器、读写位置、来源轮次、物品组成 | 解释倒序；预言正序错误 |
| 搭出 C++ 模板 | 状态怎样决定四处代码？ | 初值、方向、来源、答案四个选择，五组反例 | 正确逻辑通过全部教学用例 |
| 给错误找证据 | 如何把错误缩小到一件物品？ | 正序复用、恰好装满初值、遗漏等号三个病例 | 选择修复并复测 |
| 在陌生题里认出来 | 何时应该想到，何时不该套？ | 时间预算、硬币、可切分补给、超大容量 | 四个隐藏模型的情境判断 |
| 把扶手慢慢放开 | 能否自己完成新建模？ | 三层提示：新预算、恰好装满、二人分组 | 三道课堂数值自测；真实拓展入口 |

共 17 个课堂检验点。原有题单阅读标记继续保留，不自动转换成新课检验结果。

贯穿反例：容量 4；A=(重量 3，价值 5)，B=C=(2，3)。A 的价值和性价比都最高，但 B+C 的价值 6 更优。它揭示“不能切分”与组合约束；不要泛化为所有背包贪心都必错。

最小循环反例：容量 4，只有一件 (2，3)。正序产生 dp[2]=3，再得到 dp[4]=6，来源已经包含本件；倒序得到 3。若该种物品无限供应，6 合法。同一组数据用来说明“算法错了”必须相对于明确的题目条件。

原站拓展使用已收录的“入门赛 50 F · 神奇的背包”，本机参考难度 1150，已有题面与题解。它还有“无限物品至多一种”的额外条件，因此置于课堂之后，不能按 1150 的数字把它误当成最初的纯模板题。入口匹配真实题库 ID 或原题 URL，未收录时明确显示，不临时伪造题目或 AC。

## 排序与内容范围

专题目录按已有参考难度稳定升序排列；课程内部以认知依赖为主，难度为辅。原创教学小例不贴虚构 rating。候选练习按真实已知难度排序，并排除当前新编题解范围之外的题目。作者必须遵守 [题解政策](editorial-policy.md)：保留所有已有内容；新增题解限已核实且小于等于 2200 的题目，包含恰好 2200，未知难度先核验。这是 2026-10-22 用户明确的题目难度边界。

其他专题在课程完成之前标注“内容筹备中”。不能复制此课换名字，也不能给只有标题和候选题的页面标成已完成课程。完成一个专题，需要该算法自己特有的反例、推导、有效交互和迁移问题。

## 实现与数据约定

- 入口仍使用现有 `paths` 导航 ID，名称改为“算法实验室”，快捷键仍为 Ctrl+3；保留用户自定义导航名。
- `frontend/src/pages/algorithm-lab/` 放课程、可复用交互部件与纯计算模型；不修改其他会话负责的训练、排名或雷达逻辑。
- 进度复用 `ui.learningPaths.knapsack.labV1`，包含版本、章节、通过点和有界草稿；`learningPaths.activePath` 用于返回课程。经现有偏好 API 写入个人 SQLite，并沿用已有账号同步。
- 更新偏好使用函数式合并，保留其他专题、旧阅读标记和并发更改。旧标记不抵扣新课检验。真实题目通过只读训练记录。
- 固定教学语句用确定性模型计算，不执行输入字符串，不引入 `eval`，不发送用户代码到外部服务。
- 代码构造器显示的是教学状态逻辑检验。任意 C++ 程序的编译和正式提交使用现有工作台；课堂执行器不能冒称真实编译器。
- 测试始终使用一次性状态或本地 API fixture，设置 `TB_OFFLINE=1`，不读取用户训练库、不改运行中的安装目录、不实际提交原站。

## 新专题创作模板

写新专题之前先填写下列内容，然后再选择表现形式：

1. 谁来学：先修知识、第一次出现的术语、课程完成后能独立做什么。
2. 开场问题：一句话题意、小输入、约束、朴素做法、一个值得追问的失败。
3. 必要推理：从直觉到不变量/状态/决策的每一步，哪些信息足够、哪些可以舍弃。
4. 关键实验：用户能操作什么、预测什么、看见哪一段因果关系、如何复位。
5. C++ 实现：完整输入输出、关键行的理由、复杂度、边界、数值范围。
6. 三个最小错误：每个错误的触发条件、反例、错误轨迹、修复和复测。
7. 练习梯度：直接应用、只改一条条件、换题面转化；每题准备分层提示。
8. 识别与反识别：适用信号、不适用条件、规模改变；隐藏算法标签后再作答。
9. 真实练习：已核实来源与难度、所需额外知识、工作台入口、真实通过记录。
10. 验收证据：算法对照、实际 C++ 编译、错答与提示路径、断点恢复、移动端和无动画体验。

## 验收要求

- 核心算法与独立暴力枚举在大量小输入上对照；覆盖空方案、容量 0、装不下、恰好相等、重复重量、零价值和较大价值。
- 生成的正确 C++17 模板实际编译，运行同一批代表性用例；不能只用 JavaScript 结果声称 C++ 已验证。
- Playwright 从目录走完推荐路线，包括错答不通过、主动输入、切换方向、回退/播放/重置、修改数据、找错复测、提示展开、模型辨认与真实入口回调。
- 刷新后章节、输入和检验结果可恢复；旧阅读标记、其他偏好和个人正式记录保持原意。
- 桌面宽屏、窄窗口、手机宽度、浅色主题、减少动态效果均无页面横向溢出；必要的代码和表格允许局部滚动。
- 更新说明明确源码、验证记录、可体验入口及是否打包。未经发布，不改正式下载和版本号；并行开发不得覆盖其它会话的改动。

执行入口：在 `frontend` 目录运行 `npm run build`、`node tests/algorithm-lab-model.mjs`、`node tests/algorithm-lab.mjs`。验证结果保存在 `.backups/algorithm-lab-20261022/`。

本机体验：`D:\项目\TB\启动算法实验室预览.lnk` 会在后台启动仅监听本机的开发预览，并打开 `http://127.0.0.1:18836/tests/algorithm-lab-fixture.html`。也可在仓库根目录运行 `powershell -NoProfile -File scripts/preview_algorithm_lab.ps1 -Open`。独立预览的进度只留在浏览器中；正式软件中同一课程经现有个人偏好保存。预览不替换运行中的正式程序。
