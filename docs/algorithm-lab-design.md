## 本次错误的根因与教训

1. **按作者会的顺序写，没有按读者需要知道的顺序写。** 作者知道 DP 在比较不同的假设问题，读者看到的却像一次连续装包。没有交代“每一步可重新选”，就会把之前拿 A 当成后续必须保留的决定。
2. **把不同概念压进同一个词。** “前几件”“选”“处理”同时指允许使用、检查到哪件和实际拿走，行标题又只写 A。作者心中有区分，页面没有给读者区分的依据。
3. **推理对象悄悄改变。** 上方可能正在看 A、B、C，公式却固定讲 B；“这一件”“刚才”没有明确指向。补了变量定义，也不能修复这种例子断裂。
4. **把简洁误做删过渡。** 可以删除口号和重复标签，不能删除“为什么新增 B 后讨论拿不拿 B”“为什么原先的 A 可以不拿”这些必要前提。上一轮只补解释，没有重建讲解顺序。
5. **用运行正确代替讲解清楚。** 公式、数值、按钮和布局通过测试，只证明程序按设计工作。若设计保留了错误理解路径，测试照样通过。验收必须专门验证最可能的误读。
6. **递推只有后续，没有起点。** 每个答案都说来自上一步，却没有解释最早的答案如何直接由题意确定。只写“初始化为 0”也缺少状态含义和成立条件；读者无法判断这个 0 为什么可信。
7. **可视化只标一部分算式。** 虚线标了来源格，却没标当前物品价值、原答案与写回结果；还把写回后的数值和读取时的旧值混在一起。读者看见色框，仍不知道它们对应哪个运算数，必须自己拼接步骤。

教训：教学要把作者默认知道的关系写出来，尤其是问题范围、操作顺序、候选方案和最终结果之间的关系。发现误解后先重建推理链，再修改措辞。

## 教学书写基本规范

这些规范适用于后续所有算法专题，不只用于背包。

1. **先交代当前问题。** 写清给了什么、允许做什么、限制是什么、要求什么。图表与推导所在位置要能确认当前例子，不能要求读者靠上一屏记忆补全条件。
2. **一次只引入一个新概念。** 先用具体对象解释，再命名。讲下一步之前，检查它依赖的知识是否已经教过；不能借用尚未解释的术语解释新术语。
3. **区分条件、过程和结果。** “允许用 A”不是“已经拿 A”；“按 A、B、C 计算”不是“按这个顺序装包”；“可选物品数量”不是“实际拿取数量”。数组各格可能代表不同问题，必须同时展示它们各自的条件与方案，不能画成一个连续操作的对象。
4. **每一步说明变化与保留。** 增加一个候选、缩小容量或改变限制时，指出当前问题变了什么、哪些选择可以重做。条件分支写“如果拿 B”，不能把一个假设写成读者必须执行的动作。
5. **先展示选择及后果，再写符号。** 顺序是：实际物品 → 合法装法 → 重量与价值比较 → 记住小问题的答案 → 给答案命名 → 通式 → 代码。不能从可视化直接跳到公式。
6. **首次出现的符号必须能翻译回例子。** 说明符号表示什么、数的是什么、取哪个具体值。例如 i=2 必须对应“允许 A、B”，而不只写“前几件”；i−1、c−w 也要指出对应哪组物品与哪一个容量。
7. **说明为什么分这些情况、为什么读这个答案。** 新增候选 B 时，全部合法装法分成含 B 与不含 B；拿 B 后要用缩小容量下重新选出的答案，不能默认保留原先的最优装法。
8. **例子、图表、公式同步。** 同一段只围绕一个明确的当前问题。交互换了物品范围或容量，标题、装法、算式、变量说明一起更新；换例必须明确告知更改的条件和用途。
9. **用精确简短的语言，保留必要桥梁。** 删除口号、装饰标签和重复结论；保留条件、原因和容易误读之处。“当前”“之前”“这一件”必须有明确指向。长解释可以按需展开，必要定义不能藏在跳过它就无法理解的地方。
10. **按新手最可能的误读验收。** 从只知道先修知识的角度逐步读，检查是否会误认对象、把假设当指令、把范围当已选、把旧结果当不可更改。为关键误解准备反例或交互检查。计算正确、完成自测都不能单独证明已经教会。
11. **递推必须有起点和可执行的顺序。** 解释最小问题的答案为什么能由题意直接确定，再展示第一步怎样读取它。初始化必须对应状态定义和成立条件；随后说明每次引用的答案为什么已经算出、为什么两种情况覆盖全部合法方案。
12. **优化前先展示被保留的信息。** 不能用“只依赖上一行，所以压成一维”代替证明。先标出具体读取位置，再演示覆盖哪个位置、以后是否还需要旧值，以及错误顺序第一次破坏了什么条件。
13. **让图与表达式逐项对应。** 来源、增量、原答案、目标都要出现明确名称与下标；符号表达式和数值代入分开呈现。颜色之外要有文字，读取前和写回后要区分。不能只画虚线、实线，让读者猜语义。

交付前逐项自查：读者现在在解决哪个问题？每个量都解释了吗？每一步为什么能接到下一步？有没有偷偷换例？文字与图是否指同一对象？有没有把需要解释的前提当成常识？这些检查应落实到正文和交互，不能只写在设计文档里。

## 简洁与连贯的基准

- 教学同样遵守简洁原则。删除口号、任务编号、重复的课程标题、总进度与本节进度、提示计数；一个说明只放在需要它的位置。
- 目录默认收起，只保留七个章节名，选章后收起；允许用 Escape 或点击外部关闭。
- 图表必须带当前例子的条件：沿用哪一题、有哪些物品、重量与价值、总容量、每件使用次数。不能依赖读者记住前一屏。
- 先分三步演示只允许 A、允许 A/B、允许 A/B/C 时的两类装法，再按需展开表格。行标题明确写“只允许”，不用裸 A 暗示已拿。来源直接标“① 不拿”“② 剩余”，当前格标“当前”。
- 公式跟随当前物品范围与容量更新。处理第 i 条输入是计算顺序，物品名字不是优化依据；“拿 / 不拿”是候选方案的两类，代码比较它们的价值。不同容量各自保留方案，不能暗示已拿 A 就必须一直保留 A。
- 先用自然语言和实际物品解释选择，公式默认展开，左侧写完整的当前状态，如 `f[3][5] = max(...)`。首次出现 f、i、c、w、v、i−1、c−w、max 都要解释，并把具体格子对应到符号；不能从动画直接跳到通式。
- 默认页面保留必要推导和初始化。目录、提示和拓展题按需展开；后续章节也删去重复的开场文案和实现说明。

## 产品目的

“算法实验室”先经独立体验打磨，现已按用户要求接入开发主应用，待联合发布。题目用于引发思考和验证理解。面向没学过当前算法的同学，默认教学语言为 C++17。背包 DP 不要求先学动态规划；完整代码部分需要读懂变量、数组、循环和基本输入输出。

用户的原始要求归纳为：

- 各算法专题按参考难度由低到高排列；同难度保留稳定顺序，未知难度置后，绝不编造评级。
- 以问题驱动，从核心思想开始；再建立模型、实现模板、练习、迁移和排错。
- 用户要主动做决定、输入、预测和解释，不能只被动阅读。
- 可以采用动画、小游戏、动图、可交互图、代码执行轨迹等不同形式；每种形式都应解决具体的理解障碍。
- 完成后，要能从新题的条件中想到算法，有入手点，能实现，也能检查错误。
- 教学不等于把几道模板题按难度排好，更不能把阅读打勾当作已经掌握。
- 首个专题以背包 DP 进行自由实验；总结出可复用方法，供未来其它算法专题使用。

## 通用课程蓝图

采用下面的认知顺序，章节数和表现形式可根据算法调整，不机械套五个标签。

1. **遇到问题**：给一个不需要算法术语也能尝试的小任务。明确输入、限制、合法方案和优化目标。
2. **做出选择**：先让用户按直觉行动，立即反馈操作的结果。
3. **制造认知冲突**：用最小反例击破一个常见但不成立的想法；解释它为何失败，而不只宣布正确答案。
4. **共同发明方法**：从朴素枚举找重复或单调性等结构，解释为什么留下的信息足够。不提前要求用户接受公式。
5. **观察与预测**：允许改变数据、回退、单步和播放；同时呈现代码、状态、来源和当前动作。先预测，再揭晓关键结果。
6. **连接代码**：每个关键代码决定都对应一个已讲明的理由。提供完整 C++17 程序和输入格式，注明复杂度、数值范围和适用条件。
7. **有扶手的练习**：先直接应用，再改变一个条件。按需逐层提示，最后才展示完整思路。
8. **拆掉扶手**：换题面、混入不适用情形、加入规模变化，练习主动辨认和选择算法。
9. **排错与复盘**：将典型错误和能够暴露它的极小输入配对。修复后必须复测。
10. **走向真实任务**：进入现有做题工作台独立实现和正式练习。自测与正式记录保持各自含义。

全程允许自由跳转，不因答错锁住后续内容。推荐路线和待检验位置应明确可见。对“尚未讲到”的概念，要给出桥梁解释或标为后续拓展。

## 交互形式如何选择

| 读者的卡点 | 合适的交互 | 必须呈现的信息 |
| --- | --- | --- |
| 不明白要优化什么 | 小游戏、操作任务 | 约束、当前结果、是否有效 |
| 总觉得贪心没问题 | 可重试的反例 | 直觉选法与更好组合的具体差别 |
| 状态下标抽象 | 点选表格或图节点 | 自然语言定义、当前格、来源格 |
| 原地更新读不懂 | 执行器、时间版本标记 | 更新前后的值、读到哪一轮、物品来源 |
| 不知道如何写模板 | 代码拼装、关键行填空 | 每个选项对应的语义、多个反例结果 |
| 样例过了但总 WA | 缩小数据的找错实验 | 应得、实际、第一处错误、修复后结果 |
| 新题里认不出来 | 隐去标签的情境判断 | 条件差异、适用性和第一步模型 |

动画只负责解释变化，不能替代解释。提供暂停、单步、回退、重置与速度控制；不自动开始播放。切换章节卸载计时器，窗口隐藏时暂停。减少动态效果设置关闭过渡，但保留手动推演。颜色之外还应有文字和形状标记；键盘、窄屏、深浅主题均可使用。

## 反馈与提示

题目至少提供三种层次的帮助：提醒关注的条件、指出推理方向、展示完整推导。每次只展开用户要求的下一层；用户不必先连续答错才能获得提示。非常短的操作任务可只用两层。

反馈针对当前选择，例如“这个状态把容量上限误当成必须装满”，而不是笼统的“错误”。正确反馈也要给理由。作答修改后清除当次评语；历史通过可保留为“曾通过”，不假装它代表当前选项正确。自动保存章节、输入、提示展开和课堂检验；重开后可继续。

练习阶段必须先允许用户独立思考。完整推导藏在最后一级提示；不能一边要求预测，一边直接显示被预测的结果。执行轨迹用于解释已有算法，不假装运行用户输入的任意 C++ 源码。

## 背包 DP 首课

完整主线是“不超过容量、每件最多一次、最大价值”的 0/1 背包。恰好装满、完全背包、换目标和规模不适用作为边界与迁移介绍；不宣称本课覆盖全部背包变体。

| 章节 | 核心问题 | 实现形式 | 检验 |
| --- | --- | --- | --- |
| 先装一次背包 | 为什么局部最好的物品会选错？ | 5 格背包、三件装备、即时容量与价值 | 找到最优组合；解释贪心失败 |
| 读懂表格 | 各个小问题怎样求最大价值？ | 具体装法、表格、默认展开的完整等式、初始行列与逐行计算 | 解释 A 可跳过、不同容量各有方案、递推起点；补上最终格 |
| 理解倒序 | 为什么 0/1 背包要倒序？ | 不同容量并列展示、两行合并为一行、一维执行器、完整读写与价值来源 | 解释安全覆盖；预言正序错误 |
| 写出 C++ | 状态怎样决定四处代码？ | 初值、方向、来源、答案四个选择，五组反例 | 正确逻辑通过全部教学用例 |
| 找出错误 | 如何把错误缩小到一件物品？ | 正序复用、恰好装满初值、遗漏等号 | 选择修复并复测 |
| 辨认模型 | 何时应该想到，何时不该套？ | 时间、硬币、可切分补给、超大容量 | 四个情境判断 |
| 独立练习 | 能否自己完成新建模？ | 分层提示：新预算、恰好装满、二人分组 | 三道数值自测；原题链接 |

共 17 个课堂检验点。原有题单阅读标记继续保留，不自动转换成新课检验结果。

## 跟着做五道精选题

P1048 采药、P1049 装箱问题、P1060 开心的金明、P2392 考前临时抱佛脚、P1507 NASA 的食物计划。题面、样例和洛谷官方普及−评级已核对。每题围绕一个新的建模变化，提供条件高亮、小例实操、预测、关键转移填写、错误代码反例与自解释，最后进入工作台独立实现。五题的完整默认与详细题解一并进入公共库；跟做界面不默认给完整程序。

课堂解题过程和原站通过分别记录。主应用复用现有训练工作台与正式回执；独立包提供原题链接，由体验者自行实现。步骤、输入、解释和自检保存后可恢复，允许自由跳转；不以点击或自评替代算法理解。

相关详细题解按标签、正文和实际代码审计，共为 17 条已有条目补充题目特有的识别、模板差异与排错迁移，包含两组原题别名同步。既有正文、代码和图全部保留。难度超过 2200 或尚未核实的三条保持原样；不把不同背包变体统一描述成 0/1 最大值。

贯穿反例：容量 5；A=(重量 4，价值 7)，B=(3，5)，C=(2，3)。三件重量、价值各不相同。A 的价值和性价比都最高，但 B+C 的总重量 5、价值 8 更优。A、B、C 是输入标签，按记录依次计算不要求同序拿取；调换输入次序，中间表行可能改变，最终最大价值不变。

只允许 A、B 时，容量 5 的答案是 A 的 7，容量 3 的答案是 B 的 5；它们同时保留，各自代表一个独立问题。读取 C 后，容量 5 比较原答案 7 与容量 3 的答案加 C 的价值 `5+3`，更新为 8，对应把方案 A 换成 B+C。并没有往装了 A 的背包强塞 C。“不含当前物品 / 含当前物品”解释候选值的来源，`max` 执行价值比较。

递推起点由题意直接确定：`f[0][c]=0`（没有物品），`f[i][0]=0`（本例所有重量正数），交点 `f[0][0]=0`。空方案合法，目标为不超过容量的最大价值。其它格子在教学表中先留空，按第 1、2、3 行依次读取已知上一行；一维数组全 0 对应尚未处理物品的第 0 行，不是先猜好每个最终答案。

空间优化先展示 A/B 的旧行与 A/B/C 的新行；容量 5 读旧行的 5 和 3，容量 4 读旧行的 4 和 2。旧的容量 5 后续不再使用，可以被新答案覆盖。倒序保证后续用到的小容量仍是旧值。执行器以 `dp[c] ← max(dp[c], dp[c-w[i]] + v[i])` 的具体下标展示，来源 dp 标蓝、当前 v 标橙、写回位置标绿，并附读取前数值和候选装法。代码与物品卡统一从 1 编号。

最小循环反例：容量 4，只有一件 (2，3)。正序产生 dp[2]=3，再得到 dp[4]=6，来源已经包含本件；倒序得到 3。若该种物品无限供应，6 合法。同一组数据用来说明“算法错了”必须相对于明确的题目条件。

原站拓展为“入门赛 50 F · 神奇的背包”，有“无限物品至多一种”的额外条件，默认折叠，提供原题链接。独立版不提供主应用工作台或官方提交。

## 排序与内容范围

专题目录按已有参考难度稳定升序排列；课程内部以认知依赖为主，难度为辅。原创教学小例不贴虚构 rating。候选练习按真实已知难度排序，并排除当前新编题解范围之外的题目。作者必须遵守 [题解政策](editorial-policy.md)：保留所有已有内容；新增题解限已核实且小于等于 2200 的题目，包含恰好 2200，未知难度先核验。这是 2026-10-22 用户明确的题目难度边界。

按用户最新要求，目录只保留背包 DP，其他专题的未完成入口移除；已有题库和历史偏好保留。不能复制此课换名字，也不能给只有标题和候选题的页面标成已完成课程。完成一个专题，需要该算法自己特有的反例、推导、有效交互和迁移问题。

## 新专题创作模板

写新专题之前先填写下列内容，然后再选择表现形式：

1. 谁来学：先修知识、第一次出现的术语、课程完成后能独立做什么。
2. 开场问题：一句话题意、小输入、约束、朴素做法、一个值得追问的失败。
3. 必要推理：从直觉到不变量/状态/决策的每一步，哪些信息足够、哪些可以舍弃。
4. 关键实验：用户能操作什么、预测什么、看见哪一段因果关系、如何复位。
5. C++ 实现：完整输入输出、关键行的理由、复杂度、边界、数值范围。
6. 三个最小错误：每个错误的触发条件、反例、错误轨迹、修复和复测。
7. 练习梯度：直接应用、只改一条条件、换题面转化；每题准备分层提示。
8. 识别与反识别：适用信号、不适用条件、规模改变；隐藏算法标签后再作答。
9. 真实练习：已核实来源与难度、所需额外知识、工作台入口、真实通过记录。
10. 验收证据：算法对照、实际 C++ 编译、错答与提示路径、断点恢复、移动端和无动画体验。
